# 真实 key 验证流程

> ⛔ 强制关卡：禁止 mock、禁止伪造响应、禁止只做静态检查就注册。验证必须发起真实 HTTP 请求并产出真实图片文件。验证未通过的 provider 不得写入状态区。

## 步骤

1. 确认 key 已可用：
   - 首选：请用户在 pi-teacher「系统设置 → 高级配置 → 用户环境变量」添加对应变量（保存即注入 process.env，之后 bash 子进程直接可读）。
   - 用户在对话里直接给出 key 时，用 `VAR_NAME=xxx node scripts/{provider}.js …` 临时注入完成验证，并提醒用户去界面持久化，否则重启后脚本不可用。
2. 真调用：用简短测试 prompt（如「一只戴眼镜的橘猫」）完整执行一次脚本，覆盖该 provider 的核心参数。
3. 核对结果，全部满足才算通过：
   - 退出码为 0；
   - `~/pi-teacher/llm-text-to-img/` 出现本次新文件且大小大于 0；
   - stdout 末行 JSON 摘要字段齐全（ok / path，url 视接口而定）。
4. 清理：验证通过后立即删除验证图，保持用户目录干净。
5. 失败处理：按报错信息修脚本后重新验证，循环直到通过；确认接口本身不可用（服务下线、key 无效且用户不换）时，向用户说明原因并中止，不注册。
