## `materials/index.md` 的样子

```markdown
# 资料清单

- `java-concurrency.pdf` — Java 并发核心：线程安全、锁机制、并发容器
- `bilibili-BV1xx.md` — 李宏毅机器学习第 3 讲：梯度下降
```

一行一个文件：文件名 + 一句简介。模型能看懂就行，没有固定 schema。资料多了模型可以自己加分组标题。

## 全局 `AGENTS.md` 里的引导文字

> `/root/pi-teacher/materials/` 存放用户提供的资料以及从互联网获取的资料，其中 `index.md` 介绍了各个文件的内容简介。需要引用资料时先看 `index.md`，再读对应文件。
>
> 当用户发送文件或提供资料时，保存到该目录；若为长视频、媒体等文件，使用工具解析后保存为 Markdown。保存后在 `index.md` 追加一行简介。

写在全局 AGENTS.md 而不是会话组的，因为三种会话都要用。路径写绝对路径，不写 `~`，避免工具不展开。

## WebUI 上传流程

1. 用户在前端选文件，可附带文字，也可什么都不说
2. 后端把文件存到 `materials/`，文件名冲突时加后缀
3. 后端在用户消息末尾追加一行 `（附件已保存：/root/pi-teacher/materials/xxx.pdf）`，一起发进会话
4. 模型按全局 AGENTS.md 行事：读文件、在 `index.md` 追加简介。用户没说话也一样

## 为什么全局比按组好

1. **复用**：同一本书不用在两个组里传两次
2. **复习和助教会话也能用**：它们运行在 `review/`、`ta/` 目录，按组存放时它们摸不到任何资料；全局后，复习时答错可以翻回原文，助教可以据资料答疑
3. **引导文字只写一处**：全局 AGENTS.md 一段话覆盖所有会话
4. **会话组的含义更纯**：它是「同一个学习目标下的多场会话」，共享的是目标和难题清单，不是文件桶

代价：`index.md` 会变长。但它不进 AGENTS.md，只在模型需要资料时按需读，几百行也可接受。

## 确认后需要改的地方

- CONTEXT.md 的 Session Group 定义：去掉「复用资料」，改为「复用学习目标与上下文」
