# pi-web 消息渲染研究（MessageView.tsx / AnsiText.tsx）

> 研究对象：`components/MessageView.tsx`（1813 行）、`components/AnsiText.tsx`（20 行）
> 结论先行：这是一个"角色分发 → 块分发 → 每块独立组件"的三层渲染架构，工具调用/思考块均为折叠面板，性能核心是 `React.memo` 自定义比较器 + 超长内容降级。整体**可以改改就用**于学习助手。

## 1. 消息类型分发

### 1.1 顶层：按 `message.role` 分发（`components/MessageView.tsx:253-273`）

```tsx
export const MessageView = memo(function MessageView({ message, isStreaming, toolResults, ... }: Props) {
  if (message.role === "user") {
    return <UserMessageView message={message as UserMessage} cwd={cwd} onOpenFile={onOpenFile} entryId={entryId} onFork={onFork} forking={forking} onNavigate={onNavigate} prevAssistantEntryId={prevAssistantEntryId} onEditContent={onEditContent} />;
  }
  if (message.role === "assistant") {
    return <AssistantMessageView message={message as AssistantMessage} isStreaming={isStreaming} toolResults={toolResults} ... />;
  }
  if (message.role === "toolResult") {
    // Rendered inline under its toolCall — skip standalone rendering if paired
    return null;
  }
  if (message.role === "custom") {
    if ((message as CustomMessage).customType === "compaction") {
      return <CompactionMessageView message={message as CustomMessage} />;
    }
    return <CustomMessageView message={message as CustomMessage} cwd={cwd} onOpenFile={onOpenFile} />;
  }
  if (message.role === "bashExecution") {
    return <BashExecutionView message={message as BashExecutionMessage} sessionId={sessionId} />;
  }
  return null;
}, (prev, next) => { ... });  // 自定义 memo 比较器，见 §4
```

全部分支一览：

| role / customType | 组件 | 说明 |
|---|---|---|
| `user` | `UserMessageView` | 右侧蓝气泡，文本走 Markdown，图片网格，支持复制/fork/编辑重发 |
| `assistant` | `AssistantMessageView` | 模型名 + 内容块列表（文本/思考/工具调用）+ 错误 + usage |
| `toolResult` | **`null`** | 工具结果不单独渲染，由父级 `toolResults: Map<toolCallId, ToolResultMessage>` 传入，挂在对应 `toolCall` 块内部展示 |
| `custom` + `customType === "compaction"` | `CompactionMessageView` | 压缩摘要卡片（"对话已压缩" + 摘要正文 + 读写文件列表） |
| `custom`（其他） | `CustomMessageView` | 扩展自定义消息卡片，`message.display === false` 时默认折叠 |
| `bashExecution` | `BashExecutionView` | 用户自己跑的 bash，**合成一对 ToolCallContent+ToolResultMessage 复用 ToolCallBlock 渲染** |
| 其他 | `null` | 未知角色直接不渲染 |

**设计要点（为什么）**：toolResult 单独成条消息（落盘格式）但 UI 上"结果必须贴着调用"，所以用 `toolResults` Map 在渲染层配对，`role === "toolResult"` 返回 null。

### 2.2 展开后的内容：流式 vs 延迟加载（deferred）

历史消息的 thinking 内容可能被服务端剥离（省 token），标记 `block.deferred`，展开时才 fetch（`components/MessageView.tsx:904-929、151-178`）：

```tsx
useEffect(() => {
  if (!expanded || !block.deferred || content !== null) return;
  if (!sessionId || !entryId) { setError(tRef.current("i18n.thinkingUnavailable")); return; }
  let cancelled = false;
  setLoading(true); setError(null);
  loadThinkingContent(sessionId, entryId, blockIndex)
    .then((value) => { if (!cancelled) { setContent(value); setLoading(false); } })
    .catch((err) => { if (!cancelled) { setError(...); setLoading(false); } });
  return () => { cancelled = true; };
}, [expanded, block.deferred, content, sessionId, entryId, blockIndex]);
```

```tsx
{loading ? t("i18n.loadingThinking") : error ?? (block.deferred ? content : block.thinking)}
```

渲染方式：**纯文本 `<pre-wrap>`，不走 Markdown**（区别于 text 块），字号 12、`--text-muted` 色，视觉上弱化（`components/MessageView.tsx:966-981`）。

### 2.3 流式实时更新

- 流式中 `block.thinking` 就在消息对象里（`AssistantMessageView` 收到的 `message.content` 由上层每帧更新），`expanded` 时直接渲染 `block.thinking`，无需额外机制——**靠 props 变化驱动**。
- **时长统计**：`AssistantMessageView` 内 `setInterval(tick, 300)`（`components/MessageView.tsx:692-726`）轮询 `blockItemsRef.current`，首次见到某 `originalIndex` 记 `blockStartTimesRef`；一旦后继块开始，就把前一块时长定稿进 `streamingDurations`。流结束（`isStreaming` false）时把未定稿的收尾。
- **token 估算 + t/s 指示**：`estimateTokens`（CJK≈1 token/字，其他≈4 字符/token，`components/MessageView.tsx:31-41`）+ `estimateUpdatedTokens` 前缀增量缓存（64-80 行，避免每次全量重算，还处理了流式 delta 补全代理对的情况），300ms tick 里算出 `tps` 显示为彩色速度徽章（764-770 行，≥50 蓝 / ≥30 绿 / ≥15 黄 / <15 红）。

## 3. 工具调用展示（ToolCallBlock，`components/MessageView.tsx:992-1101`）——重点

### 3.1 状态模型

ToolCallBlock 只拿三个输入：`block`（调用）、`result`（可选，配对到的结果）、`duration`。**没有显式状态机**，状态是隐式推导的：

| 状态 | 判定 | 表现 |
|---|---|---|
| 参数流式输出中 | `const isStreamingInput = block.rawInput !== undefined;`（:996） | 头部预览位置显示 `t("chat.generatingToolInput")`（"generating…"）；展开时显示半成品原始文本 |
| 执行中（无结果） | `result === undefined` | 头部正常 + 无结果区；无进度信息（本组件不做进度条，只有时长） |
| 成功 | `result.isError === false` | 绿色系边框（`rgba(34,197,94,0.25)`）、展开显示结果/diff |
| 失败 | `result.isError === true` | 红色系边框（`rgba(248,113,113,0.45)`）+ 红字结果 |
| 被中断 | 本文件内仅 `BashExecutionView` 显式处理：`message.cancelled` 归入 `isError`（:1740）；通用 toolCall 无独立中断分支 | 红色错误样式 |

容器配色（:1010-1017）：

```tsx
border: isError ? "1px solid rgba(248,113,113,0.45)" : "1px solid rgba(34,197,94,0.25)",
background: isError ? "rgba(248,113,113,0.05)" : "rgba(34,197,94,0.04)",
```

### 3.2 头部（调用发起 / 执行中）

```tsx

<button onClick={() => setExpanded((v) => !v)} ...>
```

## 4. 性能优化

### 4.1 React.memo + 自定义比较器（`components/MessageView.tsx:274-292`）——核心

```tsx
}, (prev, next) => {
  return prev.message === next.message
    && prev.isStreaming === next.isStreaming
    && haveSameRelevantToolResults(prev.message, prev.toolResults, next.toolResults)
    && prev.modelNames === next.modelNames
    && prev.cwd === next.cwd
    && prev.onOpenFile === next.onOpenFile
    && prev.onOpenSession === next.onOpenSession
    && prev.entryId === next.entryId
    && prev.searchBlock === next.searchBlock
    && prev.onFork === next.onFork
    && prev.forking === next.forking
    && prev.onNavigate === next.onNavigate
    && prev.prevAssistantEntryId === next.prevAssistantEntryId
    && prev.onEditContent === next.onEditContent
    && prev.showTimestamp === next.showTimestamp
    && prev.prevTimestamp === next.prevTimestamp
    && prev.sessionId === next.sessionId;
});
```

**流式时不整列表重渲染的秘密**：靠"引用相等"短路。父组件每帧只替换正在流式的那条 `message` 对象（旧消息对象引用不变），`prev.message === next.message` 直接拦截其余所有消息的重渲染。

`haveSameRelevantToolResults`（:239-251）进一步解决"新 toolResult Map 导致全列表失效"的问题：

```tsx
function haveSameRelevantToolResults(message, previous, next): boolean {
  if (previous === next || message.role !== "assistant") return true;
  for (const block of (message as AssistantMessage).content ?? []) {
    if (block.type === "toolCall" && previous?.get(block.toolCallId) !== next?.get(block.toolCallId)) {
      return false;
    }
  }
  return true;
}
```

**只比较本消息涉及的那些 toolCallId 的结果条目**——其他消息的工具结果变化不会让本条重渲染。（注意回调稳定性也要求父级用 `useCallback`/稳定引用，否则 memo 失效。）

### 4.2 key 策略

```tsx

  <BlockView key={`${entryId ?? "stream"}-${originalIndex}`} ... />   // components/MessageView.tsx:780
))}
```

### 4.4 超长内容防御（重要）

```tsx
// Messages larger than this skip markdown rendering entirely. react-markdown +
// KaTeX + syntax highlighting on multi-hundred-KB payloads (e.g. pasted HAR or
// log dumps) freezes the browser main thread.
const MAX_MARKDOWN_CHARS = 100_000;    // components/MessageView.tsx:88
```

`SafeMarkdownBody`（:100-145）：超 10 万字符**完全跳过 Markdown 管线**，渲染成一个 "⚠ 大消息(XX KB) 点击显示" 按钮，点开是限高 420px 的纯文本 `<pre>`。这是防卡死的关键降级。

| 位置 | 限制 |
|---|---|

## 5. 图片与附件

### 5.1 统一入口 `imageSource`（`components/MessageView.tsx:1668-1676`）

```tsx
function imageSource(img: ImageContent): string {
  const flat = img as unknown as { data?: string; mimeType?: string };
  if (img.source) {
    return img.source.type === "base64"
      ? `data:${img.source.media_type};base64,${img.source.data}`
      : img.source.url ?? "";
  }
  return flat.data ? `data:${flat.mimeType};base64,${flat.data}` : "";
}
```

**双格式兼容**（代码注释写明原因）：`lib/types.ts` 的 `ImageContent` 用 `{source:{type,data,media_type,url}}`，而 pi-ai 落盘格式是扁平 `{data, mimeType}`。base64 一律转 data URL。

```tsx
}
```

用途（注释原意）：渲染 pi 扩展 widget（pi-lens / nano-context / rpiv-todo）输出的 ANSI SGR 转义序列（256/24-bit 色、粗斜下划删除线、链接）。`ansi_up` 库默认转义 HTML 实体，所以**不会注入 markup**。注意 MessageView.tsx 并未 import 它——它是独立小组件，供扩展消息/其他组件用。

## 6. 移植评估（学习助手）

### 6.1 需求匹配度

| 学习助手需求 | pi-web 现成能力 | 结论 |
|---|---|---|
| Markdown 讲解 | `MarkdownBody` + `SafeMarkdownBody`（含超长降级） | ✅ 直接用 |
| 代码块 | `MarkdownBody` 内部（react-markdown + 高亮 + KaTeX，未细读） | ✅ 直接用 |
| 工具调用（制卡/查资料） | `ToolCallBlock`：折叠头部 + JSON 参数 pre + 结果 pre + 错误样式 | ✅ 改参数预览别名即用 |
| 图片 | 用户图网格 + 结果大图 + `imageSource` 双格式 + `ImagePreview` | ✅ 直接用 |
| 思考块 | `ThinkingBlock`（可要可不要，GLM 类模型有 reasoning 时有用） | ✅ 可用，砍掉 deferred 加载更简单 |

**总体判断：能改改就用**，三层架构（role 分发 → block 分发 → 块组件）天然适配，props 接口（`message / isStreaming / toolResults` 三件套）就是干净的数据契约。

### 6.2 必须保留

1. `MessageView` 的 memo 比较器 + `haveSameRelevantToolResults`（§4.1）——**这是流式不卡的最大功臣，务必原样搬**，前提是父级保证旧消息引用不变、回调稳定。
2. `SafeMarkdownBody` 的 `MAX_MARKDOWN_CHARS` 降级。
3. `getToolCallInputText`（rawInput ?? JSON.stringify(input, null, 2)）与流式 `isStreamingInput` 判断。
4. key 用 `${entryId}-${originalIndex}` 的模式。
5. `imageSource` 双格式兼容。
6. `role === "toolResult"` 配对 Map 的设计（结果贴调用显示）。

### 6.3 建议砍掉（学习助手用不到）

- `BashExecutionView`（用户手动跑 bash + fullOutput 下载）——没有这个场景。
- `CompactionMessageView` / `CompactionFileMetadata` / `lib/compaction-summary`——上下文压缩摘要，除非也做长对话压缩。
- `SplitPatchView` / `PatchTextView` / `parseUnifiedPatch` / `lib/patch` / `isEditToolName`——编辑工具 diff 渲染。制卡/查资料工具不产出 patch；**如果制卡=写 Markdown 文件并想让用户看 diff，则保留这一整套**（它写得不错）。
- subagent 相关（`isSubagentToolDetails`、`onOpenSession`、`lib/subagent-extension`）。
- fork / navigate / editFromHere 按钮链（`onFork` / `onNavigate` / `onEditContent` / `replaceUserMessageText` / `prevAssistantEntryId`）——对话树分叉功能，V1 不需要。
- `TurnWrittenFiles` + `writtenFiles` prop。
- `skillExpansionToCommand`（slash 命令展开显示）/ `lib/slash-display`。
- 流式 token 估算 + t/s 徽章（`estimateTokens` / `estimateUpdatedTokens` / tps）——炫但非必需；可先砍，保留 300ms tick 的块时长统计（对"查资料耗时 3s"有用）。
- `AnsiText`——除非要渲染终端花哨输出。

### 6.4 需要改的地方

- `getToolPreview` 增加制卡/查资料工具的参数别名（`title`、`query`、`keywords`、`deck` 等）。
- `toolResults` 类型 `Map<string, ToolResultMessage>` 保持不变即可对接后端流式协议。
- 样式全是内联 style + CSS 变量（`--bg-panel` 等），换设计系统时主要改颜色变量，结构可保留。
- i18n（`useI18n`）可整体换成自己的文案表。

### 6.5 依赖清单（移植时要一起搬或替换）

`MarkdownBody`、`ImagePreview`、`lib/clipboard`(copyText)、`hooks/useI18n`、`lib/message-display`(getAssistantErrorMessage, isEmptyThinkingBlock)、`lib/tool-names`(isEditToolName)、`lib/thinking-expansion-preference`、`lib/types`(消息类型定义)、`lib/compaction-summary`、`lib/patch`、`lib/slash-display`、`lib/subagent-extension`、`lib/turn-written-files`（后六个随砍剪掉的组件一起删）。
