### 1.2 Enter / Shift+Enter

`handleKeyDown` 开头（`components/ChatInput.tsx:1136`）：

**IME（中日韩输入法）防误发**是这段代码最值得抄的细节（`components/ChatInput.tsx:1137-1146`）：

## 2. @ 文件引用补全（重点）

### 2.1 触发条件

光标前文本由 `extractAtQuery` 解析（`lib/file-fuzzy.ts:26-44`）：

```ts
export function extractAtQuery(textBeforeCursor: string): AtQueryMatch | null {
  const quoted = /(?:^|\s)@"([^"\n]*)$/.exec(textBeforeCursor);
  if (quoted) {
    return { start: textBeforeCursor.length - (quoted[1].length + 2), query: quoted[1], quoted: true };
  }
  const plain = /(?:^|\s)@([^\s"]*)$/.exec(textBeforeCursor);
  if (plain) {
    return { start: textBeforeCursor.length - (plain[1].length + 1), query: plain[1], quoted: false };
  }
  return null;
}
```

要点：
- `@` 必须**在行首或空白之后**——邮箱 `foo@bar` 永不触发（与 pi TUI 行为一致）。
- 支持 `@"my dir/fi` 引号形式，路径带空格时下钻依然工作。
- 每次 `onChange` 与 `onSelect`（光标移动）都重算（`components/ChatInput.tsx:1984, 1986-1989`）；无 `cwd`（新会话未选目录）则直接禁用（889-896 行）。

### 2.2 候选来源：**前端拉全量索引 + 本地模糊搜索，截断时混合服务端搜索**

1. **索引拉取**（`components/ChatInput.tsx:951-976`）：@ 菜单打开时 `fetch('/api/file-index?cwd=...')`，返回 `{ files: string[], truncated: boolean }`。**10 秒缓存**（`fileIndexMetaRef`），打字期间不重取；并发去重用 `fileIndexFetchingRef`。
2. **目录推导**：API 只返回文件路径，`buildEntriesFromFiles`（`lib/file-fuzzy.ts:59-76`）把每个 `/` 前缀都加进 dir 集合，产出 `FileIndexEntry[]`，基础排序为浅层优先 + 字母序。
3. **本地过滤** `filterFileEntries`（`lib/file-fuzzy.ts:120-138`）：对每个条目跑 `scoreEntry`，正分才保留，按 `分数 desc → 深度 asc → 字母序` 排序，**限 20 条**（`AT_RESULT_LIMIT`，空 query 直接取前 20）。
4. **服务端兜底**（`components/ChatInput.tsx:910-933`）：当索引被截断（`truncated`，大仓库超上限）时，150ms debounce 请求 `/api/file-index?cwd=...&q=...` 做全量服务端搜索；本地结果先渲染，服务端结果到达且 `query/cwd` 匹配当前 token 才替换（防竞态）；失败则保留本地结果，下次击键重试。

### 2.3 打分算法（`lib/file-fuzzy.ts:97-116`）

复刻 pi TUI 的 `scoreEntry` 阶梯，外加子序列兜底：

```ts
function scoreEntry(entry: FileIndexEntry, lowerQuery: string): number {
  const lowerPath = entry.path.toLowerCase();
  let score = 0;
  if (lowerQuery.includes("/")) {
    // 带斜杠的 query 按完整相对路径匹配 → 实现"目录下钻"
    if (lowerPath === lowerQuery) score = 100;
    else if (lowerPath.startsWith(lowerQuery)) score = 80;
    else if (lowerPath.includes(lowerQuery)) score = 50;
    else if (isSubsequence(lowerQuery, lowerPath)) score = 10;
  } else {
    // 无斜杠按 basename 匹配
    const slash = lowerPath.lastIndexOf("/");
    const lowerName = slash === -1 ? lowerPath : lowerPath.slice(slash + 1);
    if (lowerName === lowerQuery) score = 100;        // 精确
    else if (lowerName.startsWith(lowerQuery)) score = 80;   // 前缀
    else if (lowerName.includes(lowerQuery)) score = 50;     // 文件名子串
    else if (lowerPath.includes(lowerQuery)) score = 30;     // 路径子串
    else if (isSubsequence(lowerQuery, lowerPath)) score = 10; // 模糊子序列
  }
  if (entry.isDir && score > 0) score += 10;   // 目录加权
  return score;
}
```

- **子序列匹配**（`isSubsequence`，`lib/file-fuzzy.ts:78-85`）让 `"chinp"` 也能命中 `components/ChatInput.tsx`。
- **query 含 `/` 切到全路径匹配**是下钻的关键：插入 `@src/` 后，`"src/"` 前缀匹配 src/ 内所有条目（且排除 src 目录本身，因 `"src"` 不以 `"src/"` 开头）。

### 2.4 选中插入

`buildAtInsertText`（`lib/file-fuzzy.ts:157-166`）：

```ts
export function buildAtInsertText(entryPath: string, isDir: boolean, forceQuotes = false): AtInsertion {
  const p = isDir ? `${entryPath}/` : entryPath;
  const needsQuotes = forceQuotes || p.includes(" ");
  if (isDir) {
    const text = needsQuotes ? `@"${p}"` : `@${p}`;
    return { text, cursorOffset: needsQuotes ? text.length - 1 : text.length };
  }
  const text = needsQuotes ? `@"${p}" ` : `@${p} `;
  return { text, cursorOffset: text.length };
}
```

- **文件**插入 `@path `（带尾空格）→ token 关闭、菜单隐藏；**目录**插入 `@dir/`（无尾空格）→ token 仍打开，继续下钻。带空格路径用 `@"..."`，引号形式补目录时光标放在闭引号**前**（保持 token 良构）。
- `applyAtCompletion`（`components/ChatInput.tsx:978-1006`）：从 `atQuery.start` 到光标替换为插入文本，若处于引号 token 中先吞掉紧跟光标的旧 `"`；因 `setValue` 不触发 onChange，**手动重跑 `extractAtQuery`** 重新派生 token；`requestAnimationFrame` 后恢复焦点/光标/高度。
- 列表项用 `onMouseDown` + `e.preventDefault()` 而非 onClick（`components/ChatInput.tsx:1924-1927`）——防止 textarea 失焦导致 token 重算。

另有几个一次性插入辅助：`buildAtMentionText`（文件浏览器的 @ 按钮，目录也闭合）、`buildFileLineMentionText`（`@path:12` / `@path:12-30` 行引用，`lib/file-fuzzy.ts:179-185`）。

## 3. 斜杠命令

**支持**。触发条件（`components/ChatInput.tsx:841-843`）：

```tsx
const slashQuery = value.startsWith("/") && !/\s/.test(value.slice(1))
  ? value.slice(1).toLowerCase()
  : null;
```

即：**value 以 `/` 开头且首 token 无空白**才开菜单（避免正文中间的路径误触发）。

候选来源两层：

1. **内置** `BUILTIN_SLASH_COMMANDS`（`components/ChatInput.tsx:144-151`）：`compact` / `reload` / `name` / `session` / `copy` / `clone`，其中 `session`、`copy` 标了 `availableWhileStreaming: true`（生成中仍可用，847-849 行生成中只保留这些）。
2. **外部** props `slashCommands`（来源 `builtin | extension | prompt | skill`，`SLASH_SOURCES`，171 行），**懒加载**：菜单首次打开时调 `onLoadSlashCommands()`，`slashCommandsRequestedRef` 防重（`components/ChatInput.tsx:1287-1302`）。打开时还会顺带拉 `/api/skills?cwd=` 获取 skill 休眠标注（1307-1329 行）。

过滤与排序（845-863 行）：`name.includes(query) || description.includes(query)`，再按 `slashMatchRank`（精确 0 / 前缀 1 / 子串 2 / 描述 3，`components/ChatInput.tsx:187-195`）→ 来源序（builtin < extension < prompt < skill）→ `TEXT_COLLATOR` 字母序。渲染时按来源分组。

键盘：Tab 补全为 `/name `（`applySlashCommand`，1053-1066 行）；Enter 时若输入已是该命令**精确全文**（`isExactSlashCommand`）则直接发送，否则先补全（1197-1214 行）——这是很顺手的"两段式确认"。方向键导航用了**几何最近算法** `getNextSlashIndex`（1090-1131 行）：按候选按钮的 `getBoundingClientRect` 中心点算欧氏近似距离（垂直 delta×1000 + 水平 delta），支持 Left/Right 在分组间横移；退化为常规 ±1。

发送时 `runBuiltinCommand`（822-828 行）把 builtin 命令转交 `onBuiltinCommand` prop，未处理则回落普通发送；无附件才允许走 builtin。命令是否清空输入由 `canClearBuiltinCommandInput`（167-169 行）决定。

### 4.3 处理与压缩

`processImageFiles`（`components/ChatInput.tsx:715-742`）：

- 过滤 `type.startsWith("image/")` 且 `size <= MAX_ATTACHED_IMAGE_BYTES`（**10MB**，`lib/image-attachments.ts:1`）；
- 上限 `MAX_ATTACHED_IMAGES = 10` 张，`pendingImageCountRef` 记录异步处理中的数量防并发超额；
- 每张过 `compressImageFile`（`components/ChatInput.tsx:259-285`）：**>1MB 且非 GIF** 时用 `createImageBitmap` + canvas 缩到最长边 **1024px**、JPEG **0.85** 质量，白底填充（透明 PNG 转 JPEG 不发黑）；仅当压缩结果确实更小才采用，否则回退原始 `FileReader.readAsDataURL`；
- `previewUrl = URL.createObjectURL(file)` 供预览缩略图，删除/替换时 `revokeImagePreview` 回收（337-341 行只回收 `blob:` 前缀）。

### 4.4 发送方式：**纯 base64，无上传**

```tsx

  data: string;      // base64, no prefix
  mimeType: string;
  previewUrl: string; // object URL for display

```

## 5. 草稿持久化（`lib/draft-store.ts`）

**不是 localStorage，是模块级内存 Map**（`lib/draft-store.ts:16`）：

```ts
const drafts = new Map<string, ChatDraft>();
```

- **key**：`draftKey` prop（会话标识；新会话与已落盘会话有不同 key，会话晋升时 rekey）。
- **存**：`useEffect([value, attachedImages])` 里每次变化 `setDraft`（`components/ChatInput.tsx:775-781`）；空草稿在 `setDraft` 内自动删除（34-40 行）。
- **清**：`clearInput()`（发送成功后调用）里 `clearDraft(draftKey)`（767 行）。
- **切换 key**：`draftKey` prop 变化时先把旧 key 落一份、再从新 key 恢复（783-807 行）；`rekeyDraft`（590-621 行 + `lib/draft-store.ts:85-105`）处理会话晋升，两份草稿**合并**（新提交的放前、原有内容放后）。
- **读写都用 cloneDraft** 深拷贝，防止外部引用逃逸后被改。

⚠️ **页面刷新即丢**（内存级）。好处是草稿含大体积 base64 图片也不会撑爆 localStorage 配额；代价是刷新不保。移植时若要真持久化，需把图片部分换成 IndexedDB（base64 图片放 localStorage 很容易超 5MB）。

图片从草稿恢复时 `draftImagesToAttachedImages`（298-303 行）用 `data:` URL 重建 previewUrl（blob URL 刷新后已失效），并重过 `isBase64ImageWithinLimits` 校验 + 截到 10 张。

## 6. 发送失败恢复（`lib/prompt-recovery.ts`）

`prompt-recovery.ts` 本身很薄，只导出一个**指纹函数** `userMessageKey(message)`（39-47 行）：把用户消息的文本 + 图片签名（media_type + base64 data / url 拼串）JSON 序列化为 key，兼容 string content 和块数组 content 两种格式，兼容嵌套 `block.source` 与旧扁平 `data/mimeType` 两种图片格式。

真正的恢复流程在 `hooks/useAgentSession.ts`：

1. 发送时先插入**乐观用户消息**，记录 `optimisticUserMessageKeyRef.current = userMessageKey(userMsg)`（1315 行）。
2. SSE 事件流回报 `delivered` 消息时比对（1184-1189 行）：`userMessageKey(delivered) === optimisticKey` → 投递成功；不匹配 → 提交未被接受。
3. 失败路径（请求 reject、abort 等）调用 `restoreSubmission(message, images, composerDraftKey)`（1285 / 1295 / 1383 行）→ `ChatInputHandle.restoreSubmission`（`components/ChatInput.tsx:622-685`）把已清空的文本/图片**合并回输入框**。
4. 合并策略 `mergeRestoredSubmissionText`（`lib/draft-store.ts:46-50`）：

```ts
if (!submitted.trim()) return current;
if (!current.trim()) return submitted;
return `${submitted}\n\n${current}`;   // 失败内容在前，用户其后新敲的在后
```

   图片同理合并、重校验、截到 10 张（52-67 行）。因为 `clearInput` 与失败恢复可能竞争同一帧，`restoreSubmission` 先同步写 `setDraft` + 直接更新 `valueRef`，再走 functional setState（642-664 行有详细注释解释这个"同步持久化防丢"的 design intent）。

> 简言之：**prompt-recovery.ts = 消息指纹；恢复 = "先乐观清空、失败再合并回来"**。文本永不丢的前提是"清空发生在发送成功路径、恢复路径兜底失败"这对互补操作。

|---|---|---|
| Enter | 发送（→ steering 时走 sendQueued） | 非组合、非菜单选中态 |
| Shift+Enter | 换行（默认行为，不拦截） | — |
| Enter / Ctrl+Enter | 发送 | 移动端需 Ctrl/Cmd |
| ArrowDown/Up | 菜单内移动高亮（history→slash→@ 依次接管） | 菜单开着 |
| ArrowLeft/Right | slash 菜单分组间横移（几何最近） | 仅 slash 菜单 |
| Tab | history 菜单：填入；slash 菜单：补全；@ 菜单：补全 | 各菜单开着 |
| Enter | slash：精确命令直接发送，否则补全；@：补全；history：填入 | 各菜单开着 |
| Esc | 依次：关 history 菜单 → 关 slash 菜单 → 关 @ 菜单 → 停止 agent | 1242-1256 行 |
| ArrowUp（输入为空且非生成中） | 打开 **input history 菜单**（最近 50 条去重用户输入，来自会话消息，`components/ChatWindow.tsx:467-480`） | 1242-1249 行 |

菜单滚动跟随 `scrollIntoView({ block: "nearest" })`；slash 菜单高度用 `useLayoutEffect` + ResizeObserver + visualViewport 监听动态计算**向上展开的最大高度**（`getUpwardMenuMaxHeight` / `getVisibleTopBoundary`，104-119 行 + 1346-1388 行）——移动端键盘弹出时菜单不会被裁掉。

## 8. 移植评价

### 8.1 可以近乎原样抄的（零/极低依赖）

| 模块 | 依赖 | 备注 |
|---|---|---|
| textarea 自动高度 + 200px 上限 | 无 | 直接抄，注意程序化设值后要在 rAF 里重量高度 |
| Enter/Shift+Enter + **IME 三重防护**（isComposingRef / nativeEvent.isComposing / keyCode 229 / 100ms 宽限） | 无 | 中文输入必备，很多实现漏掉 |
| `lib/file-fuzzy.ts` 全文件 | 无（纯函数） | token 提取/打分/插入文本零框架依赖，直接拷贝 |
| `lib/image-attachments.ts` | 无 | 常量 + 校验 |
| `compressImageFile` + `processImageFiles` | 浏览器 API | 粘贴/压缩/base64 全套可抄 |
| `hooks/useDragDrop.ts` | react | 记得接在窗口容器上，经 ref 转发进输入框 |
| 草稿 `lib/draft-store.ts` | 无 | 若接受"刷新丢失"则整抄；要持久化需把图片改走 IndexedDB |
| @ 补全的菜单 UI + 键盘流 + 150ms debounce 服务端兜底 | 1 个 API | 纯交互逻辑可抄，端点自建 |
| 菜单向上展开的高度计算（getUpwardMenuMaxHeight） | 无 | 移动端键盘场景很实用 |

### 8.2 需要自建后端/数据源的

- `/api/file-index?cwd=&q=`：文件索引 + 截断标记。**这是 @ 补全的唯一外部依赖**，返回相对路径数组即可，`buildEntriesFromFiles` 前端自动补目录。
- slash 命令数据源（props `slashCommands` + `onLoadSlashCommands`）：builtin 六条可留可裁，extension/prompt/skill 来源按需。
- 发送/中断回调本身（`onSend` / `onAbort`）——任何聊天 UI 都有。

### 8.3 pi-web 特有、建议砍掉或简化的

| 功能 | 处置建议 |
|---|---|
| **steer / followUp**（流中插话） | pi 的 streaming 概念。最简方案：生成中禁用输入（或仅保留 Esc/Stop 按钮）；若要保留，`sendQueued` + 两个按钮 + 黄色边框整体可抄，但需要后端支持两种排队语义 |
| ModelSelector / modelNames / modelList / modelScopeWarnings | 砍。与输入框正交，属顶栏职责 |
| toolPreset（chat-only/read-only/default/full）下拉 | 砍或独立成"设置" |
| thinkingLevel 及其映射 | 砍 |
| compact / compaction 全套（onCompact、compactResult、Stop Compaction 按钮） | 砍 |
| queuedMessages 面板 + onRecallQueue | 随 steer/followUp 一起处理 |
| **bash 模式**（`!` / `!!` 前缀） | pi 的 shell 直通能力，依赖后端执行；砍 |
| input history 菜单（ArrowUp 召回历史输入） | 依赖会话消息历史，有历史就能抄，便宜 |
| soundEnabled / onAudioUnlock | 砍 |
| i18n（useI18n 的 t()） | 换硬编码文案即可，注意其 key 体系（chat.xxx）遍布全文 |
| draftKey rekey 逻辑（会话晋升） | 无多会话草稿隔离需求则砍掉，只留单 key 存取 |
| `prompt-recovery.ts` + restoreSubmission | 若你也有"乐观消息 + SSE 确认"的发送模型，**强烈建议保留**（体验关键）；若是简单 await fetch 失败重填，可简化为 catch 里把 message 塞回 state |

### 8.4 抄的时候的坑

1. `setValue` 程序化设值**不触发 onChange**，@ token 必须手动 `extractAtQuery` 重派生（994-997 行注释明说）。
2. 列表项一律 `onMouseDown` + `preventDefault()` 保住 textarea 焦点，否则点选后光标跳尾部、token 重算错乱。
3. `clearInput` 与异步失败恢复存在竞态，pi 的解法是同步写 ref + setDraft 再 functional setState（625-664 行），移植时容易简化出 bug。
4. slash 触发条件是"首 token 无空白"，且 `handleSend` 里 `isStreaming` 时普通消息直接 return——这两个静默 return 用户无感知，pi 靠 steer 按钮和 placeholder 提示补足，砍 steer 时要换成 placeholder/禁用提示。
5. 移动端 Enter 语义反转（必须 Ctrl+Enter）由 `useIsMobile` 驱动，若不用其检测方式需自己判断触屏。
