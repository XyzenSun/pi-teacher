## 1. Tailwind 4 配置

### 1.1 传统 config 基本为空

`tailwind.config.ts` 只有 content 扫描路径，`theme.extend` 空、`plugins` 空：

`tailwind.config.ts:9-12`
```ts
theme: {
  extend: {},
},
plugins: [],
```

### 1.2 CSS-first 配置是主战场

CSS 采用 Tailwind 4 的 CSS-first 方式，`@import "tailwindcss"` + `@theme`：

`app/globals.css:1-19`
```css
@import "tailwindcss";

@theme {
  --color-bg: var(--bg);
  --color-bg-panel: var(--bg-panel);
  --color-bg-hover: var(--bg-hover);
  --color-bg-selected: var(--bg-selected);
  --color-border: var(--border);
  --color-text: var(--text);
  --color-text-muted: var(--text-muted);
  --color-text-dim: var(--text-dim);
  --color-accent: var(--accent);
  --color-accent-hover: var(--accent-hover);
  --color-user-bg: var(--user-bg);
  --color-assistant-bg: var(--assistant-bg);
  --color-tool-bg: var(--tool-bg);
  --color-bg-subtle: var(--bg-subtle);
  --font-mono-font: var(--font-mono);
}
```

- 结论：**传统 config 与 CSS-first 并存，但传统 config 是空壳**，实际全部设计令牌都靠 `@theme` + 运行时 CSS 变量两层转发。
- `@theme` 块通过颜色语义命名把手动配色语义化（`bg` / `bg-panel` / `border` / `text` / `accent` / `user-bg` / `assistant-bg` / `tool-bg`），且把 `--color-*` 直接 `var()` 转发到 `:root` 里定义的基础变量。这样做的目的是**运行时切换暗色只需改 `:root` / `html.dark` 上的基础变量，Tailwind utility（如 `bg-bg-panel`、`text-text-muted`）自动跟随**。
- 字体令牌 `--font-mono-font` 转发 `--font-mono`，而 `--font-mono` 又来自 `next/font` 加载的 `Noto_Sans_Mono`（见 `layout.tsx:8-12`，注入 `--font-noto-mono`）。
- 自定义 utility / component：**没有** `@utility` / `@layer` / `@custom-variant`。所有样式都是普通 CSS 类（`.markdown-body`、`.panel-resize-handle`、`.sidebar-container` 等）直接写在全局 CSS 里，配合少量 Tailwind utility 类使用。

### 1.3 断点

Tailwind 默认断点（sm 640 / md 768 / lg 1024 …），`@theme` 里没有自定义断点。项目里自定义的 CSS 断点清一色围绕 **640 / 641 和 480 / 960**：

- `@media (max-width: 640px)`：移动端布局（`globals.css:1034, 1358`、`settings.css:1072`）
- `@media (min-width: 641px)`：桌面布局（`globals.css:1257`）
- `@media (max-width: 480px)`：窄屏手机收起次级工具栏（`globals.css:902`、`useIsMobile.ts:8`）
- `@media (min-width: 960px)`：宽桌面右侧文件面板参与分栏（`globals.css:1287`）

## 2. 设计令牌（CSS 变量）

### 2.1 命名约定

两层结构：

1. **基础层**：`:root` 定义 `--bg`、`--border`、`--text`、`--accent` 这类短名基础变量，暗色在 `html.dark` 重定义同名变量。
2. **语义层**：`@theme` 里 `--color-*` 把它们映射成 Tailwind utility（见上面第 1.2 节）。

另有少量功能性变量：

- `--app-viewport-height`：键盘弹出/滚动条变化时的可视高度（PWA 特有，`globals.css:60-64`、`useViewportHeight.ts`）
- `--font-mono` / `--font-noto-mono`：字体栈与 next/font 变量
- `--sidebar-width`、`--right-panel-width`：可拖拽面板宽度，运行时由 hook 写入（`globals.css:1267`、`1294`）
- `--catppuccin-icon-light` / `--catppuccin-icon-dark`：文件图标背景（`globals.css:66-88`）

### 2.3 其他 CSS 结构

- `@media (display-mode: standalone)`（`globals.css:60-64`、`settings.css:1142-1160`）：PWA standalone 模式处理状态栏/安全区。
- `@media (prefers-reduced-motion: reduce)`（`globals.css:302, 1219`）：全套动画降级。
- `@media (pointer: coarse)`（`globals.css:769`）：触屏加大点击热区（如关闭按钮 44px）。
- keyframes 若干：`drop-zone-in`、`drop-ripple`、`notice-shelf-in/out`、`blink`、`spin`、`pulse` 等（`globals.css:1148-1219`）。

## 3. 暗色模式（重点）

### 3.1 实现方式：`class` 策略 + 跟随系统

- 在 `<html>` 上切换 **`.dark` class**（不是 `data-attribute`，也不是纯 CSS `prefers-color-scheme`）。
- 全局 CSS 用 `.dark`/`html.dark` 选择器覆盖变量（见 2.2）。
- 支持 **`light` / `dark` / `auto`（跟随系统）** 三种偏好，`auto` 用 `matchMedia("(prefers-color-scheme: dark)")` 解析，并监听系统变化实时切换。

### 3.2 `hooks/useTheme.ts` 完整分析（180 行）

核心架构：**模块级单例 + `useSyncExternalStore`**（官方推荐的避免 React Context 重复渲染/多音叉(torn)状态的做法）。

**状态存哪**：
- 模块作用域变量 `state: ThemeState | null`（`useTheme.ts:20`），即 store 单例；
- 持久化到 `localStorage` 的 key `"pi-theme"`，只存 preference（`light`/`dark`/`auto`），`ThemeState = { preference, theme }`（`useTheme.ts:8-16`）；
- SSR 端返回固定的 `SERVER_SNAPSHOT = { preference: "auto", theme: "light" }`（`useTheme.ts:17`）。

**getSnapshot / getServerSnapshot / subscribe 三件套**（`useTheme.ts:96-112`）：
```ts
function subscribe(cb: () => void): () => void {
  listeners.add(cb);
  ensureState();
  ensureSystemListener();
  syncAutoThemeFromSystem();
  return () => { listeners.delete(cb); };
}

function getSnapshot(): ThemeState {
  return ensureState();
}

function getServerSnapshot(): ThemeState {
  return SERVER_SNAPSHOT;
}
```

**避免 FOUC 的两道防线**：

1. `layout.tsx:65-69` 在 `<head>` 里内联一段立即执行的脚本，在 React 水文之前就根据 localStorage + 系统偏好给 `<html>` 加上 `.dark`：
`app/layout.tsx:66-69`
```html
<script dangerouslySetInnerHTML={{
  __html: `(function(){try{var t=localStorage.getItem("pi-theme");var dark=t==="dark"||((t==null||t===""||t==="auto")&&window.matchMedia("(prefers-color-scheme: dark)").matches);if(dark)document.documentElement.classList.add("dark")}catch(e){}})();`,
}} />
```

2. `ensureState()`（`useTheme.ts:51-60`）在首次客户端订阅时把 store 解析出来的主题再 `applyDomTheme(theme)` 同步一次，保证与内联脚本一致；React 侧用 `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)` 使 hydration 不报错（server 快照固定为 light）。

**跟随系统**：
- `ensureSystemListener()`（`useTheme.ts:83-94`）监听三件事：`matchMedia("(prefers-color-scheme: dark)")` 的 `change` 事件、`window.focus`、`document.visibilitychange`（后者用于后台回来时校准，因为部分浏览器后台会漏发 scheme 事件）。
- `syncAutoThemeFromSystem()`（`useTheme.ts:75-81`）：仅当 preference 为 `auto` 时把解析结果同步到 store，且**不写 localStorage**（`persist: false`）。

**切换逻辑**：
- preference 三态循环 `light → dark → auto`（`PREFERENCE_CYCLE`，`useTheme.ts:16`、`nextPreference` 114-117）。
- `toggleTheme` / `setThemePreference`（`useTheme.ts:122-171`）保存 preference 并应用主题。
- **彩蛋——View Transitions API 圆形擦拭动画**：切换时若 `<html>` 支持 `document.startViewTransition` 且用户未开启 reduced-motion，则用圆形 clip-path 动画过渡（`useTheme.ts:131-165`），配合 `globals.css:90-103` 屏蔽 UA 默认十字淡化、设置 z-index 层级：
`app/globals.css:93-103`
```css
::view-transition-old(root),
::view-transition-new(root) {
  animation: none;
  mix-blend-mode: normal;
}
::view-transition-old(root) { z-index: 1; }
::view-transition-new(root) { z-index: 2; }
```
动画半径圆心取点击坐标 `origin`（默认屏幕中心），`transition.ready` 后再 `Element.animate()` 播放 `clip-path` 展开（450ms，`cubic-bezier`）。

**对外 API**：`theme`、`preference`、`setThemePreference`、`toggleTheme`、`isDark`（`useTheme.ts:173-179`）。

## 4. 组件库

### 4.1 package.json 里**没有**任何 UI 组件库

dependencies 里与 UI 相关的只有：`next`、`react`、`react-dom`、`remark-*` / `react-markdown` / `rehype-*`（Markdown 渲染）、`katex`（公式）、`mermaid`（流程图）、`react-syntax-highlighter`（代码高亮）、`ansi_up`（终端 ANSI 色）。**没有 shadcn / Radix / headlessui / 任何 component 库。**

### 4.2 交互组件全部手写

从 CSS 即可看出，对话框用的是原生 `<dialog>`（`.image-preview-dialog`、`.mermaid-zoom-dialog` 带 `[open]`、`::backdrop` 伪元素，`globals.css:701, 776`），下拉/菜单/面板/滚轮步进器等均为自定义类 + 原生 HTML 事件实现。可拖拽面板用的是 Pointer Events + `setPointerCapture`（详见第 5 节）。主题切换按钮、文件预览、通知栏等也都是手写组件。

### 4.3 图标

CSS 中出现 `.catppuccin-file-icon`（`globals.css:66-88`），并借助 `@supports mask-image` 将 SVG alpha 通道当蒙版用，使文件图标跟随应用文字色板（而非 Catppuccin 的多彩语言色）：`background: var(--text-dim); mask-image: var(--catppuccin-icon-light/dark)`。说明图标很可能使用 **Catppuccin 图标集 + CSVG mask 技术**统一成单色。其余小图标（关闭按钮、切换等）大概率也是内联 SVG/字符，具体实现不在本次只读范围内。

## 5. 响应式与移动端

### 5.1 断点定义

见 1.3。核心约定：**640px 为移动/桌面分界**（CSS `@media` 与 JS `useIsMobile` 保持一致，注释 `app/globals.css` 与 `useIsMobile.ts:5` 明确这对齐关系），480px 为窄屏进一步折叠，960px 为宽桌面分栏。没有使用 Tailwind 的 md/lg 断点做布局切换，而是手写 `@media` + 自定义类。

### 5.2 `useIsMobile`（43 行）

- 两个查询：`(max-width: 640px)` 和窄屏 `(max-width: 480px)`（`useIsMobile.ts:6-8`）。
- 同样用 `useSyncExternalStore` 订阅 `matchMedia` 的 `change`，**SSR 安全**：服务端与首次客户端绘制都返回 `false`（桌面），hydration 后再同步真实视口（`useIsMobile.ts:27-38` 注释明确这一设计）。
- 导出 `useIsMobile()` 和 `useIsNarrowMobile()` 两个 hook。

### 5.3 `useViewportHeight`（94 行）：解决移动键盘弹出问题

解决的具体问题是 **iOS 独立 PWA 下，键盘弹出时 `100dvh` 仍按布局视口计算，导致输入框被键盘挡住、可能触发整页滚动**（`useViewportHeight.ts:32-36` 注释）。

实现：
- 监听 `window.visualViewport` 的 `resize` / `scroll`，以及 `window` 的 `resize` / `focusin` / `focusout` / `pageshow`。
- `shouldUseVisualViewportHeight()`（`useViewportHeight.ts:12-20`）判定条件：**有 editable 元素聚焦 && 页面未缩放(`viewportScale≈1`) && `innerHeight - viewport.height > 1`**（即键盘确实挤压了可视区）。
- 满足条件时把 `--app-viewport-height` 设为 `viewport.height`，否则移除属性回落到 CSS 里的 `100dvh`/`100vh` fallback（`useViewportHeight.ts:53-57`）。`html, body` 高度使用 `height: var(--app-viewport-height, 100dvh)`（`globals.css:113`）。
- 用 `requestAnimationFrame` 节流，解决 WebKit 在 PWA 收起键盘时 `resize` 先于 `viewport.height` 落定、导致键盘高度残留的问题（`useViewportHeight.ts:70-73`）。

### 5.4 `useResizablePanel`（285 行）：可拖拽调宽

- 纯 **Pointer Events** 实现：`onPointerDown` 记录起点并 `setPointerCapture`、拖 `onPointerMove` 按 `growthDirection`（`left`/`right`）计算新宽度并 `clamp`、`onPointerUp/Cancel/LostPointerCapture` 收尾（`useResizablePanel.ts:128-178`）。
- 宽度写入 **CSS 变量 `cssVariable`**（如 `--right-panel-width`），面板宽度由 CSS `width: var(...)` 读取（`useResizablePanel.ts:91-94`、`globals.css:1294`）。这样动画宽度变化不触发 React 重渲染。
- **状态持久化**：drag 结束时 `commitWidth(..., { forcePersist: true })` 写入 `localStorage`（key 为 `storageKey`）；挂载时从 localStorage 恢复并重新 clamp（`readStoredWidth`/`writeStoredWidth`，`useResizablePanel.ts:41-58, 212-222`）。还支持 `getDefaultWidth` / `getMaxWidth` 动态边界。
- 细节：拖拽期间锁 `body` 的 `cursor`/`userSelect`；键盘可达（`role="separator"` + `tabIndex=0`，方向键步进 `12px`，Shift 步进 `32px`，`Home`/`End` 最小/最大，`Enter` 复位）；失焦/隐藏页面时取消拖拽；`resize` 时重新 clamp。
- 配套的 clamp 逻辑在 `lib/panel-layout.ts` 的 `clampPanelWidth`（不在本次只读范围内）。

## 6. 移植评估

**结论：这套样式方案可以拿来当"配色与主题机制"的基础，但组件层需要自己补充一套（如 shadcn）。**

### 值得直接借鉴/复用

1. **两段式令牌结构**（`@theme` 语义色 → `:root`/`html.dark` 基础变量）非常干净：换主题只改一行 CSS 变量，Tailwind utility（`bg-bg-panel`、`text-text-muted`）自动跟随。这个模式可以原样搬进新项目。
2. **暗色模式全套**：`useTheme.ts` 的 useSyncExternalStore + localStorage + matchMedia 监听 + `layout.tsx` 内联脚本防 FOUC + View Transitions 切换动画，实现成熟可直接复制。对学习助手这类需要"跟随系统"的产品正好。
3. **`useIsMobile` / `useViewportHeight` / `useResizablePanel`** 三个 hook 都解耦良好、SSR 安全，对话界面 + 复习界面用得上（尤其移动端键盘场景和侧边卡片栏拖宽）。
4. 断点约定（640 移动 / 960 桌面）与 markdown-body 渲染样式可直接复用。

### 需要自己补/重做的

1. **组件库是零**。下拉菜单、对话框、tooltip、弹出层、Toast 全部手写。好消息是原生 `<dialog>` + Tailwind 组合足够搭一个学习助手；坏消息是如果追求组件速度，**装 shadcn/ui（基于 Radix，天然配 Tailwind 4）会是更快的路径**——shadcn 正好能复用这套 `--color-*` 语义令牌（把 shadcn 的 CSS 变量层替换成 pi-web 的变量名即可）。
2. **令牌覆盖不全**：没有圆角/阴影/字号/间距令牌，新项目若要用 shadcn 或统一设计规范，需要在 `@theme` 里补 `--radius-*`、`--shadow-*` 等。
3. `@theme` 里字体只映射了等宽体 `--font-mono-font`，正文用系统字体，没有自定义可变字体。

### 建议

- **"改造复用"比"从头搭"更适合**：保留 pi-web 的令牌结构 + 主题 hook + 视口/面板 hook，删掉 pi 特有的终端/markdown/文件预览类（`settings.css`、大量 `.markdown-body`、`.extension-*`），再装 shadcn/ui 补齐交互组件。这样颜色、暗色、响应式、可拖拽四大基础设施都有了，组件开发效率比全手写高。
- 新项目落地时注意：本报告未读 `components/` 目录，交互组件（菜单、tooltip 等）的手写实现细节未核验，若要参考请另行查看源码。
