## 1. 会话列表结构

### 1.1 列表项显示的信息（`SessionItem`，SessionSidebar.tsx:1982）

每个列表项固定高度 54px（`SESSION_LIST_ITEM_HEIGHT`，SessionSidebar.tsx:19），高 54 的一半给标题、一半给元数据行：

- **标题**：`session.name || displayFirstMessage.slice(0, 50) || session.id.slice(0, 12)`（SessionSidebar.tsx:2028）。其中 `displayFirstMessage` 会把 SDK 展开的 `<skill>` 块折叠回用户输入的 `/skill:name` 命令（SessionSidebar.tsx:2027，`skillExpansionToCommand`）。**列表不显示模型，不显示 git 状态**（只有 worktree 分支名，见下）。
- **元数据行**（第二行，SessionSidebar.tsx:2222-2244）三段：
  1. 状态位：`isRunning ? <RunningSessionIndicator/> : isUnread ? <UnreadSessionIndicator/> : <formatRelativeTime(session.modified)>`（SessionSidebar.tsx:2223-2229）
  2. 消息数：`t("sidebar.messagesCount", { count: session.messageCount })`（SessionSidebar.tsx:2230）
  3. worktree 分支名（仅当 `session.isWorktree && session.branch`，SessionSidebar.tsx:2231-2244）：一个 git 分叉图标 + 分支名，title 提示 `Worktree: ${session.cwd}`

选中态：左侧 2px accent 边 + `var(--bg-selected)` 背景；hover 用 `var(--bg-hover)`（SessionSidebar.tsx:2117-2122）。

### 1.2 分组机制：**两层都是「项目」为第一层**

pi-web 的结构是「**项目（cwd） → 会话**」，不是树形工作区折叠面板：

1. **第一层：项目选择器（dropdown，不是树）**。侧边栏头部有一个 cwd 选择按钮（SessionSidebar.tsx:1097-1155），点开下拉列出所有「最近项目」`getRecentProjects(allSessions)`（SessionSidebar.tsx:947），每个项目一行：路径 + 活动徽标（`showProjectActivity`，SessionSidebar.tsx:1946，显示 running 数 + unread 数）。项目超过 8 个时出现前端过滤输入框（`showProjectFilter = recentProjects.length > 8`，SessionSidebar.tsx:948）。
2. **第二层：扁平的会话列表**。选中项目后，`filteredSessions = sessionsForProject(allSessions, selectedProject.key)`（SessionSidebar.tsx:973-975），列表内**不再分组、不按时间分段**，直接展示该项目的全部会话。

### 1.3 `project-groups.ts` 的分组逻辑（全文 53 行）

三个纯函数，全部以服务端提供的稳定 `projectKey`（`workspaceKeyOf(session)`，来自 `lib/workspace-memory`）为身份：

```ts
// lib/project-groups.ts:12-26
export function getRecentProjects(sessions: readonly SessionInfo[]): RecentProject[] {
  const latestByProject = new Map<string, { root: string; modified: string }>();
  for (const session of sessions) {
    const root = session.projectRoot ?? session.cwd;
    if (!root) continue;
    const key = workspaceKeyOf(session);
    const previous = latestByProject.get(key);
    if (!previous || session.modified > previous.modified) {
      latestByProject.set(key, { root, modified: session.modified });
    }
  }
  return [...latestByProject.entries()]
    .sort((a, b) => b[1].modified.localeCompare(a[1].modified))
    .map(([key, { root }]) => ({ key, root }));
}
```

- `getRecentProjects`：按 projectKey 去重，取每个项目 `modified` 最新的会话时间，按最近活动排序。注意 root 取 `session.projectRoot ?? session.cwd`，即**服务端解析的项目根**优先于会话所在目录（子目录会话归属到 repo 根）。
- `getProjectActivity`（lib/project-groups.ts:28-46）：按 key 聚合 `running` / `unread` 计数，供项目选择器徽标用。
- `sessionsForProject`（lib/project-groups.ts:48-53）：`filter((session) => workspaceKeyOf(session) === projectKey)`。

**关键设计**：key 是「服务端计算的稳定身份」，前端从不自己推导路径语义（`WorktreeState` 注释里明确写了 "Stable server-computed identity; never derive OS path semantics here"，SessionSidebar.tsx:137）。同一 repo 的多个 worktree 通过 `projectKey` 归入同一项目（"Sessions of every worktree in the selected project are shown together"，SessionSidebar.tsx:953 注释）。

### 1.4 会话家族（subagent 折叠）

列表渲染的是 `sessionFamilies = listSessionFamilies(filteredSessions)`（SessionSidebar.tsx:1005，来自 `lib/session-family`）。每个 family = 一个 root 会话 + 其 subagent 子会话；但实际渲染时（SessionSidebar.tsx:1703-1730）**只渲染一行 root**，`isSelected/isRunning/isUnread` 取 family 内任一会话的并集（`familySessions.some(...)`），显示时间用 `family.latestModified` 冒泡到 root 行上。`SessionItem` 有 `depth/hasChildren/collapsed` props（SessionSidebar.tsx:1990-2005）支持子行，但当前调用处没传——subagent 树是被压平成单行 + 状态聚合的。

### 1.5 虚拟化列表

列表是手写的窗口化虚拟列表（无第三方库）：

```ts
// components/SessionSidebar.tsx:21-31
export function getSessionListIndices(count: number, scrollTop: number, viewportHeight: number, focusedIndex = -1): number[] {
  const overscan = 8;
  const visibleCount = Math.ceil((viewportHeight || 600) / SESSION_LIST_ITEM_HEIGHT) + overscan * 2;
  const start = Math.max(0, Math.min(Math.floor(scrollTop / SESSION_LIST_ITEM_HEIGHT) - overscan, count - visibleCount));
  const end = Math.min(count, start + visibleCount);
  const indices = Array.from({ length: end - start }, (_, offset) => start + offset);
  if (focusedIndex >= 0 && focusedIndex < start) indices.unshift(focusedIndex);
  if (focusedIndex >= end && focusedIndex < count) indices.push(focusedIndex);
  return indices;
}
```

滚动监听用 rAF 节流（SessionSidebar.tsx:428-435），viewport 高度用 `ResizeObserver`（SessionSidebar.tsx:436-446）。绝对定位 `top: index * 54` 排布，容器高度 `sessionFamilies.length * 54`（SessionSidebar.tsx:1700）。**前置条件是固定行高**——若我们的两层结构需要可变高度的分组头，此实现要改。

## 2. 列表交互

| 操作 | 触发方式 | 实现细节 |

| **删除** | hover 行尾垃圾桶按钮（SessionSidebar.tsx:2297-2325） | **有行内确认**：点击后该行原位切换为「删除会话名 + 红色 Delete + Cancel 两个按钮」的确认态（SessionSidebar.tsx:2129-2169），高度不变避免列表回流；**Shift+点击跳过确认直接删**（`handleDeleteClick`，SessionSidebar.tsx:2069-2076，按钮 title 就是 `sidebar.deleteWithShiftClick`）。确认后 `DELETE /api/sessions/{id}`（SessionSidebar.tsx:2062） |

## 3. 运行状态指示

### 3.1 显示方式

- 运行中：`RunningSessionIndicator`（SessionSidebar.tsx:1875-1911）——accent 色旋转圆弧，SVG `<animateTransform>` 纯 CSS 动画（`dur="0.9s"`），title 为 `sidebar.agentRunning`。替换了相对时间的位置。
- 有新活动（后台完成未读）：`UnreadSessionIndicator`（SessionSidebar.tsx:1913-1938）——青色 `#0891b2` 圆点 + 扩散涟漪动画。
- 项目级：`showProjectActivity`（SessionSidebar.tsx:1946-1980）在项目下拉里显示 `running 数 + unread 数`；此外选择器按钮本身（未展开时）有一个 8px accent 圆点 `hasOtherWorkspaceActivity`（SessionSidebar.tsx:1141-1154）表示「其他工作区有动静」。

### 3.2 怎么知道哪些会话在运行：**轮询（不是 SSE）**

```ts
// components/SessionSidebar.tsx:161
const RUNNING_SESSIONS_POLL_MS = 2500;
```

核心机制（SessionSidebar.tsx:513-581）：

- 每 2.5s `fetch("/api/agent/running")`（轻量接口，只返回 `{sessionListVersion, runningSessionIds, completionNotificationSuppressedSessionIds}`）。
- **页面不可见时暂停轮询**（`document.visibilityState !== "visible"` 就不 schedule、abort 在途请求；`visibilitychange` 回到可见立即 poll 一次，SessionSidebar.tsx:523-571）。
- **轮询结果是权威来源**：`runningPollAuthoritativeRef`（SessionSidebar.tsx:416-418）——一旦轮询交付过快照，慢的 `/api/sessions` 响应里的 running 集不得覆盖它（SessionSidebar.tsx:467-473）。
- **版本号驱动的增量刷新**：`/api/agent/running` 响应携带 `sessionListVersion`，与本地 `sessionListVersionRef` 不一致才 `loadSessions()` 重拉完整列表（SessionSidebar.tsx:551-554），避免每次都全量扫描。
- 完成检测：对比 `previousRunningSessionIdsRef` 与当前集合，差集中排除「当前选中会话」「subagent」「服务端声明静默的会话」得到 `completedWithNotifications`，把这些 id 加入 `unreadSessionIds` 并触发 `onBackgroundTaskDone`（提示音，SessionSidebar.tsx:591-628）。
- unread 集合持久化到 `localStorage`（key `pi-web:unread-session-ids`，SessionSidebar.tsx:159、181-202），刷新页面不丢；选中该会话即清除（SessionSidebar.tsx:630-638）。
- `runningSessionIds` 通过 `onRunningSessionIdsChange` 回传 AppShell（SessionSidebar.tsx:583-585），AppShell 再用于标题栏等（AppShell.tsx:115-121）。

SSE 只用于**消息流本身**（ChatWindow 的 agent 事件流），列表运行状态完全靠轮询 + 版本号。**后台任务完成提示**另有 Web Push（iOS PWA 挂起时收不到轮询，AppShell.tsx:82-89）。

## 4. 搜索（SessionSearch.tsx）

- **请求后端**，非前端过滤：`fetch('/api/sessions/search?q=...')`（SessionSearch.tsx:29），300ms debounce + `AbortController` 取消在途请求（SessionSearch.tsx:27-40）。
- **全文搜索**（消息内容），不只是标题：结果项 `{session, entryId, blockIndex, before, match, after}`（SessionSearch.tsx:53），渲染 `before <mark>match</mark> after` 三段式摘要（SessionSearch.tsx:66-68）。即搜到的是具体 entry/block，点击 `onSelectSession(session, entryId, blockIndex)` 直接**跳到那条消息**（配合 AppShell 的 `searchTarget` 状态，AppShell.tsx:132-135）。
- 每行还显示会话标题（`session.name || session.firstMessage`）、cwd、相对时间（SessionSearch.tsx:61-64）。
- 有 `truncated` 标志（结果被截断时提示 `sidebar.sessionSearchPartial`，SessionSearch.tsx:50-52）。
- 打开方式：头部放大镜按钮切换 `sessionSearchOpen`（SessionSidebar.tsx:1077-1092）；激活条件 `sessionSearchOpen && query.trim()`（SessionSidebar.tsx:407）。**搜索时整树列表被替换**：`<SessionSearch ...>{children}</SessionSearch>` 包裹列表容器，`!open || !search ? children : 搜索结果`（SessionSearch.tsx:43）。`refreshKey` 传的是 `sessionListVersion`，版本变化时重查。
- 另注意：**项目下拉的过滤框**（`projectFilter`，SessionSidebar.tsx:949-951、1172-1198）是纯前端 `includes` 过滤，与全文搜索是两套。

## 6. 可拖拽面板（useResizablePanel.ts）

通用 hook，侧边栏与右面板各实例化一次。要点：

- **Pointer Events** 而非 mouse 事件：`onPointerDown` 记录 `DragState {pointerId, startX, startWidth, ...}` 并 `setPointerCapture`（useResizablePanel.ts:128-150），支持触摸。拖动期间给 `document.body` 设 `cursor: col-resize` + `userSelect: none`，结束后还原（useResizablePanel.ts:106-109）。
- **方向抽象**：`growthDirection: "right" | "left"`，移动量乘 `direction = growthDirection === "right" ? 1 : -1`（useResizablePanel.ts:161-162）——侧边栏向右长、右面板向左长，同一 hook 复用。
- **宽度走 CSS 变量 + ref 双通道**：拖动中不 setState（避免整树 re-render），只 `panelRef.current.style.setProperty(cssVariable, ...px)` 并同步 `widthRef.current`（`applyLiveWidth`，useResizablePanel.ts:91-94）；松手才 `setWidth` 提交 React 状态（`commitWidth`，useResizablePanel.ts:96-104）。
- **持久化：`localStorage`**，`storageKey` 由调用方传入——侧边栏 `pi-sidebar-width`、右面板 `pi-right-panel-width`（AppShell.tsx:183、195）。只在值变化或 `forcePersist` 时写（useResizablePanel.ts:102）；挂载时恢复并重 clamp（若视口变小导致 clamp 后与存储不同，回写修正值，useResizablePanel.ts:212-222）；`window.resize` 时重 clamp（useResizablePanel.ts:224-233）。
- **clamp**：`clampPanelWidth(candidate, minWidth, effectiveMaxWidth())`，其中 `effectiveMaxWidth = Math.min(maxWidth, getMaxWidth())`——静态上限与响应式上限（`getSidebarMaxWidth` 等）取小。
- **完整 a11y**：`role="separator"` + `aria-orientation/valuemin/valuemax/valuenow/valuetext`；**键盘**：←/→ ±12px（Shift ±32px），Home/End 到最小/最大，Enter **双击语义重置默认宽**（useResizablePanel.ts:189-210、273）。
- 边界鲁棒性：中键点击忽略（`event.button !== 0` return，useResizablePanel.ts:129）；`buttons === 0` 时视为松手（useResizablePanel.ts:155-158）；`pointercancel / lostpointercapture / blur / visibilitychange` 全部会 `finishResize`（useResizablePanel.ts:172-178、235-250）；卸载时恢复 body 样式（useResizablePanel.ts:252-259）。

## 7. TabBar（components/TabBar.tsx，118 行）

**管的是「文件标签」，不是多开会话**。`Tab` 接口一目了然：

```ts
// components/TabBar.tsx:8-16
export interface Tab {
  id: string;
  label: string;
  filePath: string;
  sourceSessionId?: string | null;
  initialDisplayMode?: FileViewerDisplayMode;
  viewerState?: FileViewerState;
  viewerRevision?: number;

```

- 每个标签对应右侧 FileViewer 打开的一个文件（`filePath` + 记住查看模式/滚动的 `viewerState`），`sourceSessionId` 标记来源会话（例如从聊天里的 diff 链接打开）。图标用 `getFileIcon(tab.label, 13)`。

- 单会话多开不存在——会话切换永远走左侧列表；标签栏只服务于文件浏览。
- 纯 inline style，无拖拽排序、无固定/钉住。

## 8. 移植评价：「工作区 → 对话」两层结构

### 8.1 结论：**分组机制可直接复用，UI 形态需要从「下拉选择器」改成「树」**

pi-web 的数据层天然就是「工作区（projectKey）→ 多个会话」：

- `workspaceKeyOf` 稳定 key + `getRecentProjects` + `sessionsForProject` 三个纯函数**原样可用**（lib/project-groups.ts 全文），只要我们的 SessionInfo 有 `projectRoot/cwd/modified` 等价字段。
- 「一个工作区含多次对话」正是 `sessionsForProject` 语义；worktree 归并到同一 projectKey 的逻辑对我们是免费收益（多个克隆/目录挂同一工作区）。
- **但 UI 是「下拉选项目 + 扁平列表」**，两层是互斥视图（选了项目才看到会话）。若我们要「左侧树形：工作区可展开列出对话、多个工作区同时可见」，需要把 dropdown 改为可折叠分组列表——这属于新 UI，非复用。好消息是 `SessionItem` 的 `depth` prop、`getRecentProjects` 的排序、`getProjectActivity` 的计数徽标都可以直接喂给树形渲染。

### 8.2 需要适配的部分

| 项 | 问题 | 建议 |
|---|---|---|
| **固定 54px 虚拟列表** | 两层树有分组头（可变高度），`getSessionListIndices` 假设固定行高 | 会话不多可先放弃虚拟化；量大则改 flatten 后带 `type: "group"/"item"` + 前缀高度数组 |
| **选中会话即切换 cwd** | `handleSelectSessionFromList` 把 cwd 跟着会话走（SessionSidebar.tsx:931-935） | 两层结构下工作区是显式状态，应改为「先选工作区，再在其上下文中开会话」，去掉这个隐式联动 |
| **新建会话的 lazy spawn** | 客户端 UUID + `transient` 标记 + 首条消息才起进程 | 机制优秀，保留；`transient` 对重命名/删除的豁免逻辑一并保留 |

### 8.3 建议砍掉的部分（按用户指定）

- **worktree**：`WorktreeState`、`/api/worktrees` 全套（SessionSidebar.tsx:127-146、719、846、882）、worktree switcher UI（wt* 一大片 state，SessionSidebar.tsx:390-400）、`session.isWorktree && session.branch` 的分支名显示（SessionSidebar.tsx:2231-2244）、以及 worktree 相关测试 `SessionSidebar.worktree.test.mjs`。**注意 `workspaceKeyOf` 本身别砍**——它是分组身份，只是不再需要「切换 worktree」的交互。
- **git 状态**：列表里本来就没有 git status；侧边栏的 FileExplorer「changed files」计数（`changesCount`/`changesCollapsed`，SessionSidebar.tsx:408-409、1782-1796）若 FileExplorer 不移植则随之删除。
- **模型显示**：列表项不显示模型，无需处理；顶栏的 `sessionStats`/`contextUsage` 等属于 ChatWindow 范畴，不在本块。

### 8.4 值得直接搬走的部分

1. **运行状态轮询模式**（2500ms `/api/agent/running` + `sessionListVersion` 增量刷新 + visibility 暂停 + 权威来源 ref）——比 SSE 推送简单可靠，强烈建议复用（SessionSidebar.tsx:413-628）。
2. **行内删除确认 + Shift 跳过**（同高不回流，SessionSidebar.tsx:2129-2169）与**行内重命名**（含 fallback 不持久化的细节，SessionSidebar.tsx:2037-2055）。
3. **unread 持久化到 localStorage + 选中即清除 + subagent 静默排除**（SessionSidebar.tsx:159-202、630-638）。
4. **useResizablePanel 整个 hook**（含键盘 a11y、localStorage 持久化、响应式互让 max 宽度，panel-layout.ts 一起搬）。
5. **移动端 overlay 抽屉 + backdrop + mobileSidebarReady 防闪**（AppShell.tsx:1812-1845）。
6. **全文搜索跳转定位**（search 结果带 `entryId/blockIndex` 直达消息，SessionSearch.tsx）——若我们的后端能提供等价的搜索接口。
