### 1.2 自动滚到底部 + 流式输出保持贴底

**关键设计 1：流式消息不进 `messages` 数组，单独渲染在列表尾部。** 这样 `messages` 引用稳定，整棵消息树（React.memo 的 MessageView）在流式期间不重渲染（注释见 `components/ChatWindow.tsx:447-459`）：

```tsx
// components/ChatWindow.tsx:943-945

  <MessageView message={streamState.streamingMessage as AgentMessage} isStreaming modelNames={modelNames} cwd={messageCwd} onOpenFile={onOpenFile} onOpenSession={onOpenSession} />
)}
```

流式时若还没有内容，显示 phase 文案（运行工具/等待模型）的 pulse 动画（`components/ChatWindow.tsx:947-951`）。

**关键设计 2：贴底判定是"跟随（follow）"状态机，不是每次都 scrollTo。** 核心三个函数（`lib/chat-lazy-load.ts:26-51`，原文照贴）：

```ts
// lib/chat-lazy-load.ts:26-33
export function isScrollAtTail(
  scrollTop: number,
  clientHeight: number,
  scrollHeight: number,
  tolerance = CHAT_SCROLL_TAIL_TOLERANCE,
): boolean {
  return scrollTop + clientHeight >= scrollHeight - tolerance;
}

// lib/chat-lazy-load.ts:35-51
export function getLiveFollowAttached(
  wasAttached: boolean,
  previousScrollTop: number,
  scrollTop: number,
  clientHeight: number,
  scrollHeight: number,
  reattachTolerance = CHAT_SCROLL_REATTACH_TOLERANCE,
): boolean {
  if (isScrollAtTail(scrollTop, clientHeight, scrollHeight)) return true;
  if (scrollTop < previousScrollTop) return false;
  if (
    !wasAttached
    && scrollTop > previousScrollTop
    && isScrollAtTail(scrollTop, clientHeight, scrollHeight, reattachTolerance)
  ) return true;
  return wasAttached;
}
```

- 贴底容差 `CHAT_SCROLL_TAIL_TOLERANCE = 8`（`lib/chat-lazy-load.ts:2`）：离底 ≤8px 就算贴底。
- 重吸附容差 `CHAT_SCROLL_REATTACH_TOLERANCE = 96`（`lib/chat-lazy-load.ts:3`）：脱离后重新向下滚动、且离底 ≤96px 时重新接上流。

### 1.3 用户上滚后会被强制拉回底部吗？——不会（做得对）

从 `getLiveFollowAttached` 的逻辑可以直接读出行为：

1. `scrollTop < previousScrollTop`（用户向上滚）→ **立即返回 false，脱离跟随**。此后流式输出不再拉动滚动条，用户可以安静地读历史。
2. 脱离后**只有用户主动向下滚且接近底部（96px 内）才重新吸附**，不存在定时器式的强制拉底。
3. `wasAttached` 状态保持：如果用户既没上滚也没贴底（比如停在中间然后内容变长），保持原状态不突变。

即经典的 attach/detach 状态机，避免"边流式边被拽到底"的糟糕体验。

### 1.4 运行中：prompt anchor（题头锚定）——把用户问题钉在视口顶部

这是 pi-web 最有特色的一段：agent 运行时，通过一个高度可变的 spacer 把"用户刚发的那条消息"顶到视口顶端，输出从其下方流出、向上滚走（效果类似终端）。实现是 `useLayoutEffect`（`components/ChatWindow.tsx:487-573`），核心片段：


高度计算委托给纯函数（`lib/chat-lazy-load.ts:53-64`）：spacer 高度 = 用户消息顶部位置 − 16 − 当前内容结束位置 + 视口高，即把内容末端"顶"到用户消息正下方一屏：

```ts
// lib/chat-lazy-load.ts:53-64
export function getPromptAnchorSpacerHeight(
  targetTop: number,
  contentEnd: number,
  clientHeight: number,
): number {
  const clampedTargetTop = Math.max(0, targetTop);
  if (clampedTargetTop === 0) return 0;
  return Math.max(0, Math.ceil(
    clampedTargetTop + clientHeight - Math.max(0, contentEnd),
  ));
}
```

维护细节（`components/ChatWindow.tsx:503-548`）：
- `updatePromptAnchorSpacer` 内部先校验四个 ref（container/messageContent/userMessage/spacer）都没被换掉才执行，防止会话切换后的陈旧闭包改错 DOM。
- **直接写 `spacer.style.height`，不经过 React state**——避免流式期间每 chunk 一次 React 重渲染。
- 用 `requestAnimationFrame` 合并测量（`promptAnchorMeasureFrameRef`，541-546），并用 `ResizeObserver` 同时观察 container、messageContent、userMessage 三个元素（549-554），内容尺寸一变就重算。
- 首次测量到需要撑高时，调用 `scrollUserMsgToTop()` 把用户消息滚到顶（`needsInitialAdjustment`，526-536）。
- 流式每个 chunk 到达后通过 `useLayoutEffect` 手动触发一次重测（`components/ChatWindow.tsx:575-577`）：

```tsx

```

右侧还有一个 `ChatMinimap`（36px 宽的 minimap/滚动定位条，移动端隐藏，`components/ChatWindow.tsx:978-986`），并通过 `revealHistoryForMinimap` 在 minimap 跳转历史时把 visibleCount 直接翻倍展开（`components/ChatWindow.tsx:473-475`）。

## 2. 历史消息懒加载

### 2.1 常量与纯函数（lib/chat-lazy-load.ts 全部逻辑）

```ts
// lib/chat-lazy-load.ts:1-24（原文）
export const VISIBLE_PAGE_SIZE = 50;
export const CHAT_SCROLL_TAIL_TOLERANCE = 8;
export const CHAT_SCROLL_REATTACH_TOLERANCE = 96;

export function getVisibleRenderWindow(totalCount: number, visibleCount: number): {
  startIndex: number;
  hasMore: boolean;
} {
  const clampedVisibleCount = Math.min(Math.max(visibleCount, 0), Math.max(totalCount, 0));
  const startIndex = Math.max(0, totalCount - clampedVisibleCount);
  return { startIndex, hasMore: startIndex > 0 };
}

export function getNextVisibleCount(currentVisibleCount: number, pageSize = VISIBLE_PAGE_SIZE): number {
  return currentVisibleCount + pageSize;
}

export function captureScrollDistance(scrollHeight: number, scrollTop: number): number {
  return scrollHeight - scrollTop;
}

export function restoreScrollTop(scrollHeight: number, savedDistance: number): number {
  return Math.max(0, scrollHeight - savedDistance);
}
```

设计要点：**懒加载以"末尾 N 条"为窗口**（`startIndex = totalCount - visibleCount`），从底部往顶部生长——对话类 UI 的自然方向。`captureScrollDistance`/`restoreScrollTop` 保存与恢复的是"距底部距离"而非绝对 scrollTop，天然兼容头部插入内容。

### 2.2 首屏加载多少条

首屏渲染 **50 条**（`VISIBLE_PAGE_SIZE`）。`visibleCount` 初始即 50（`components/ChatWindow.tsx:299`）：

```tsx
// components/ChatWindow.tsx:296-302

// top, load another page while keeping the scroll position stable.

const prevScrollDistanceRef = useRef<number | null>(null);

```

两层"加载更多"：本地已加载消息被 slice 截断时是本地展开（增大 visibleCount）；`hasEarlierMessages && historyCursor` 表示服务器还有更早的历史（`useAgentSession` 维护游标），此时才发请求 `loadContext(sid, activeLeafId, oldestId)`（分页从服务端再拉一页并 prepend，见注释 `components/ChatWindow.tsx:365-367`）。

### 2.3 触发机制：IntersectionObserver（不是 scroll 事件）

哨兵 div 渲染在列表顶部（`components/ChatWindow.tsx:934-938`），observer 以滚动容器为 root（`components/ChatWindow.tsx:358-384`，原文照贴）：

```tsx
// components/ChatWindow.tsx:356-384
// IntersectionObserver on the sentinel div at the top of the message list.
// When it becomes visible, load the next page of older messages.
useEffect(() => {
  const sentinel = sentinelRef.current;
  const container = scrollContainerRef.current;
  if (!sentinel || !container) return;
  const observer = new IntersectionObserver(
    (entries) => {
      if (!entries[0]?.isIntersecting) return;
      // No older history loaded yet: fetch the previous page from the server
      // and prepend it (loadContext handles prepend + scroll anchoring).
      // Skip while a page is already loading or nothing older exists.
      if (loadingOlderRef.current) return;
      if (!hasEarlierMessages) return;
      const oldestId = historyCursor;
      if (!oldestId) return;
      const sid = session?.id ?? sessionIdRef.current;
      if (!sid) return;
      loadingOlderRef.current = true;
      prevScrollDistanceRef.current = captureScrollDistance(container.scrollHeight, container.scrollTop);
      void loadContext(sid, activeLeafId, oldestId).finally(() => {
        loadingOlderRef.current = false;
      });
    },
    { root: container, threshold: 0 }
  );
  observer.observe(sentinel);
  return () => observer.disconnect();
}, [historyCursor, hasEarlierMessages, session, activeLeafId, loadContext, sessionIdRef, scrollContainerRef]);
```

哨兵 UI 只是提示文本，不可点（`components/ChatWindow.tsx:932-941`）：

```tsx
// components/ChatWindow.tsx:930-941
const { startIndex } = getVisibleRenderWindow(rendered.length, visibleCount);
const hasMore = startIndex > 0 || hasEarlierMessages;
return (
  <>
    {hasMore && (
      <div ref={sentinelRef} className="py-3 text-center text-xs text-text-muted">
        {t("chat.loadEarlier")}
      </div>
    )}
    {rendered.slice(startIndex)}
  </>
);
```

注意懒加载的窗口作用在**渲染产物 `rendered`**（用户消息 + 折叠的过程组等渲染单元）上，不是原始 `messages` 数组上。

### 2.4 加载后滚动位置不跳（难点）——三段式配合

**第 1 步：请求前快照"距底距离"**（上节代码中 `captureScrollDistance`，写进 `prevScrollDistanceRef`）。

**第 2 步：prepend 后保证已加载内容不被 slice 剪掉**（`components/ChatWindow.tsx:386-390`）：

```tsx
// components/ChatWindow.tsx:386-390
// Keep the rendered window at least as large as what's loaded, so prepended
// (older) pages stay visible instead of being sliced off the top.
useEffect(() => {
  setVisibleCount((current) => Math.max(current, messages.length));
}, [messages.length]);
```

**第 3 步：`visibleCount` 增大后恢复 scrollTop**（`components/ChatWindow.tsx:392-400`）：

```tsx
// components/ChatWindow.tsx:392-400
// After visibleCount increases (more messages prepended), restore the
// scroll position so the viewport doesn't jump.
useEffect(() => {
  if (prevScrollDistanceRef.current == null) return;
  const container = scrollContainerRef.current;
  if (!container) return;
  container.scrollTop = restoreScrollTop(container.scrollHeight, prevScrollDistanceRef.current);
  prevScrollDistanceRef.current = null;
}, [visibleCount, scrollContainerRef]);
```

时序是：DOM 里新内容已经插入（rendered.slice 的窗口变大）→ 本 effect 在绘制前把 scrollTop 设回"距底同样距离"的位置 → 用户视觉上原地不动，新的旧消息出现在上方。

**保护性细节：**
- `loadingOlderRef`（普通 ref，非 state）做 in-flight 去重，避免 observer 抖动期间重复请求。
- 搜索定位场景也复用同一套锚定：定位历史里的搜索命中时，先把 200 条更多历史拉进来，同样先 `captureScrollDistance` 再置空，并一次性把 visibleCount 提到 `(entryIds.length + 200) * 2`（`components/ChatWindow.tsx:313-339`），随后 `scrollToMessage(element)` 滚到目标元素并做 2.5 秒背景闪烁高亮（`components/ChatWindow.tsx:341-354`）。

## 4. 会话列表渲染

### 4.1 虚拟滚动：有，手写的固定行高窗口化

无第三方虚拟列表库。行高固定 **54px**（`SESSION_LIST_ITEM_HEIGHT`，`components/SessionSidebar.tsx:19`），只挂载可视窗口 ±8 行 overscan（`components/SessionSidebar.tsx:21-31`，原文照贴）：

```tsx
// components/SessionSidebar.tsx:17-31
// Fixed row height for the session list. SessionItem renders at exactly this
// height, so the list can be windowed (only the visible slice is mounted).
const SESSION_LIST_ITEM_HEIGHT = 54;

export function getSessionListIndices(count: number, scrollTop: number, viewportHeight: number, focusedIndex = -1): number[] {
  const overscan = 8;
  const visibleCount = Math.ceil((viewportHeight || 600) / SESSION_LIST_ITEM_HEIGHT) + overscan * 2;
  const start = Math.max(0, Math.min(Math.floor(scrollTop / SESSION_LIST_ITEM_HEIGHT) - overscan, count - visibleCount));
  const end = Math.min(count, start + visibleCount);
  const indices = Array.from({ length: end - start }, (_, offset) => start + offset);
  // Keep a focused row mounted so scrolling cannot discard an inline rename.
  if (focusedIndex >= 0 && focusedIndex < start) indices.unshift(focusedIndex);
  if (focusedIndex >= end && focusedIndex < count) indices.push(focusedIndex);
  return indices;
}
```

配套：
- scroll 事件用 `requestAnimationFrame` 节流更新 `listScrollTop`（`components/SessionSidebar.tsx:428-435`）；
- 视口高度用 `ResizeObserver` 跟踪（`components/SessionSidebar.tsx:436-446`）；
- 容器内用绝对定位撑总高、每行 `position: absolute; top: index * 54`（`components/SessionSidebar.tsx:1696-1715`）：

```tsx
// components/SessionSidebar.tsx:1700-1715（节选）
<div style={{ position: "relative", height: sessionFamilies.length * SESSION_LIST_ITEM_HEIGHT }}>
  {virtualIndices.map((index) => {

    ...

      onBlur={() => setFocusedSessionId(null)}
```

- **焦点行强制挂载**（上面 `focusedIndex` 分支）：行内重命名输入框不会因为滚出窗口被卸载丢焦点。
- 行内容等高交换（正常/重命名/删除确认三种形态都占 54px，`components/SessionSidebar.tsx:2103-2107` 注释），列表永不 reflow。

### 4.4 运行/未读状态的数据来源：轻量轮询

- `/api/agent/running` 每 **2500ms** 轮询（`RUNNING_SESSIONS_POLL_MS`，`components/SessionSidebar.tsx:161`）；
- **页面不可见时停表**（visibilitychange 暂停/恢复），并用 AbortController 取消在途请求（`components/SessionSidebar.tsx:513-581`）；

## 5. 会话列表交互

### 5.1 新建

**纯前端生成 UUID，不发任何请求**；agent 在用户发第一条消息时才 spawn（`components/SessionSidebar.tsx:937-945`）：

```tsx
// components/SessionSidebar.tsx:937-945
const handleNewSession = useCallback(() => {
  if (!selectedCwd) return;
  // Generate a temporary UUID client-side — no backend call needed.
  // Pi will be spawned lazily when the user sends the first message.
  const tempId = typeof crypto.randomUUID === "function"
    ? crypto.randomUUID()
    : `${Date.now().toString(36)}-${Math.random().toString(36).slice(2)}-${Math.random().toString(36).slice(2)}`;
  onNewSession?.(tempId, selectedCwd);
}, [selectedCwd, onNewSession]);
```

顶部"新建"按钮在没选项目时禁用（`components/SessionSidebar.tsx:1039-1076`）。此类临时会话 `session.transient` 为真，禁重命名/删除（`components/SessionSidebar.tsx:2032`、`2058`）。

### 5.2 切换

点击行 → `handleSelectSessionFromList`：把 cwd 切到该会话的 worktree、乐观插入（若会话不在本地列表先塞进去防闪烁）、再回调父级 `onSelectSession`（`components/SessionSidebar.tsx:927-935`）：

```tsx
// components/SessionSidebar.tsx:927-935
// Clicking a session moves the effective cwd to that session's worktree.
// Done on the click path (not via the selectedCwd prop sync) so it also
// works when the prop value won't change — e.g. re-clicking the already
// open session after manually switching worktrees.
const handleSelectSessionFromList = useCallback((s: SessionInfo, entryId?: string, blockIndex?: number) => {
  setAllSessions((current) => current.some((session) => session.id === s.id) ? current : [s, ...current]);
  if (s.cwd) setSelectedCwd(s.cwd);
  onSelectSession(s, false, entryId, blockIndex);
}, [onSelectSession]);
```

## 6. 移植评估（学习助手：工作区列表 + 对话窗口）

### 6.1 结论速览

| 模块 | 可移植性 | 建议 |
|---|---|---|
| `lib/chat-lazy-load.ts`（64 行纯函数） | ★★★★★ 零改动直接抄 | 原样复制 |
| 贴底跟随状态机（attach/detach + 双容差） | ★★★★★ 概念抄、代码抄 | 两个函数即全部逻辑 |
| 懒加载 + 滚动锚定三段式（observer→snapshot→restore） | ★★★★☆ | 抄流程；`loadContext` 换成自己的分页 API |
| 会话列表固定行高虚拟化 | ★★★★☆ | 50 行内手写方案，无依赖，直接搬 |
| 行内重命名/删除/等高三态行 | ★★★★★ | 交互模式直接搬 |
| prompt anchor（题头钉顶） | ★★★☆☆ | 仅"边问边答长时间输出"场景需要；普通问答 chat 不必 |
| ChatWindow 整体 | ★★☆☆☆ | 耦合 agent 协议（SSE/扩展/工具消息/分支树），重写外壳、只取算法 |
| SessionSidebar 整体 | ★★★☆☆ | 分组骨架契合"工作区→对话"，砍掉 worktree/git/explorer 后骨架可用 |

### 6.2 滚动与懒加载值不值得抄——值得，理由

1. **算法与框架/协议完全解耦**：`lib/chat-lazy-load.ts` 是 64 行无依赖纯函数（数字进数字出），单测友好。
2. **"距底距离"锚定法**（`captureScrollDistance`/`restoreScrollTop`）比保存绝对 scrollTop 更稳：头部 prepend 内容时不依赖对新增高度的预估。
3. **双容差分离**是同类产品里少见的细节：8px 贴底容差判"在尾部"，96px 重吸附容差给脱离后回流的用户一个宽松的"接上"条件；`scrollTop < previousScrollTop` 一票否决，保证用户上滚读历史时绝不被拽回——这正是问题里点名的"糟糕体验"，pi-web 明确避开了。
4. **懒加载用 IntersectionObserver 而非 scroll 事件**，无阈值抖动、无需监听销毁滚动监听；配 `loadingOlderRef`（ref 而非 state，不触发渲染）做 in-flight 去重。
5. 流式消息独立渲染（不进 `messages`）+ `toolResultsMap` 用 `useMemo` 稳定引用，让长历史在流式期间零重渲染——学习助手如果也有流式答题，这是必须抄的性能模式（注释原文见 `components/ChatWindow.tsx:447-459`）。

移植时的注意点：
- 懒加载窗口作用在**渲染产物**上（`rendered.slice(startIndex)`，`components/ChatWindow.tsx:930-941`），若你的渲染层有折叠分组，应对齐这一点，否则截断会切断折叠组。
- 恢复 scrollTop 的 effect 依赖 `[visibleCount]`（`components/ChatWindow.tsx:394-400`），锚定只应在"因加载变大"时触发一次（快照后即置 `null`），复制时别把它改成常驻比较。
- 未见"滚到底部"浮动按钮；若学习助手要加，`isScrollAtTail` 判断显隐即可，成本很低。

### 6.3 会话列表怎么改

与需求映射直接：
- **项目选择器（顶部下拉）→ 学习工作区切换**；`getRecentProjects`/`sessionsForProject` 换成按 workspace 字段分组即可。项目下拉里的 running/unread 徽标逻辑（`showProjectActivity`，`components/SessionSidebar.tsx:1946-1980`）可以照搬。
- **session family → 每个工作区下的多次对话**：把 `family.root + subagents` 换成"工作区内按时间倒序的对话"即可，选中/运行/未读的 some() 判定逻辑照搬。
- **必须砍掉**：worktree 切换器（~700 行）、FileExplorer 区、`/api/cwd/validate` 路径验证、scramble 标题动画、更新检查。
- **值得保留的行为**：2500ms 可见性感知轮询 + `sessionListVersion` 版本比对避免全量刷新；`sessionLoadIdRef` 防慢响应回写；未读标记 localStorage 持久化；新建会话前端 UUID 懒 spawn；删除 Shift 跳过确认。
- 若学习助手没有"会话在后台运行"的概念，running/unread 轮询整块可删，虚拟化与三态行仍是净收益。
