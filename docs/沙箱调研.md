# 免费云沙箱调研报告

> 调研日期：2026-09-07。免费额度政策变化极快，所有额度信息均标注「截至」日期或「待验证」；查不到确切数字的一律写「待验证」，未编造任何数字。

## 调研背景

pi-teacher 是本地 Docker 部署的单用户 AI 学习助手（agent 底座为 Pi）。主容器内只有 Node.js 一个语言运行时，刻意不装 Python（ADR-0015），算法题的代码执行依赖远程沙箱；沙箱由 agent 侧的 skill 或插件封装（载体待定，ADR-0027 排除了 MCP）。

用户已有自研方案：本地 docker 快速生成「基础开发环境 + 暴露 SSH 端口」的执行容器。本调研回答：**有哪些值得接入的、提供免费额度的云沙箱**，最终与自研方案统一封装后交给 agent 使用。

核心诉求：

- **教学场景的代码执行**：运行用户练习的代码片段与小项目，非生产负载
- **能否对齐自研方案的 SSH 形态**（有裸 SSH 的优先级高）
- **免费额度**是否够一个重度学习者使用
- 可自托管、可自定义镜像/环境的优先级高

## 1. E2B

**定位**：面向 AI agent 的云沙箱（e2b.dev），「给 LLM 一个安全的云 VM 跑生成的代码」，是该品类的开创者。

### 免费额度（截至 2026-09，来源：docs.e2b.dev/billing）

- Hobby 套餐：$0/月，**新用户一次性 $100 免费 credits**，无需信用卡
- **注意是一次性而非每月续发**，用完即需付费（按秒计费，$0.000014/s 起，约 $0.05/小时/沙箱）
- Hobby 限制：单沙箱最长连续运行 1 小时；最多 20 个并发沙箱；8 vCPU / 8 GiB 内存 / 10 GiB 磁盘；每秒最多创建 1 个沙箱
- Pro：$150/月，单沙箱 24 小时，100+ 并发，但无额外 credits

按 $0.05/小时估算，$100 credits ≈ **约 2000 沙箱小时**。对教学场景（每次执行几分钟）非常充裕。

### SSH 支持（来源：docs.e2b.dev/sandbox/ssh-access）

**可以，但非原生**。E2B 官方文档给出方案：模板里装 `openssh-server` + `websocat`，通过 sandbox 暴露端口走 WebSocket 代理：

```bash
ssh -o 'ProxyCommand=websocat --binary -B 65536 - wss://8081-%h.e2b.app' user@<sandbox-id>
```

支持交互式 shell、SCP/SFTP 文件传输。形态上与自研方案（裸 SSH 到容器端口）不同：它是 **exec API 为主 + SSH 可选补装**。

### 语言运行时

- 默认基础镜像为 Ubuntu 25.04（预装 Python 等 AI agent 常用运行时）
- **自定义镜像**：`template.fromImage("custom-image:latest")` 支持任意 Docker Hub / registry 镜像
- 模板（Template）机制：base image + env + files + commands + start cmd，构建时快照
- 模板构建环境本身就是完整沙箱，构建期甚至可以跑 Docker

### 启动延迟

- 官方称快照加载 **约 80ms**（模板提前构建，进程已运行、文件系统就绪）
- 从快照创建沙箱是「零等待」——依赖装在模板里

### API 形态

- 官方 SDK：**Python / JavaScript (TypeScript)**（E2B SDK 均开源，Apache-2.0）
- 接口形状：`Sandbox.create(template)` → `sandbox.commands.run()` / `sandbox.files.write/read` → `sandbox.kill()`；支持 pause + snapshot（保留运行进程的快照）
- REST API 亦有（docs.e2b.dev/api-reference）

### 开源与自托管

- **SDK 与模板定义开源**（github.com/e2b-dev/E2B，Apache-2.0），infrastructure 部分开源（e2b-infra）
- 官方托管平台闭源。**自托管理论可行但复杂度高**（需要 Firecracker + NATS 等一整套），社区有尝试但非官方支持路径

### 生命周期

- 单沙箱最长 1 小时（Hobby）/ 24 小时（Pro），到期自动暂停
- Paused 沙箱保留无时限；沙箱可 snapshot 后恢复
- 典型模式：exec 完即 kill，按秒计费

### 地域与网络

- 官方文档未列明可选地域（Hobby 默认分配），美国/欧洲节点为主
- 国内直连情况**待验证**（`*.e2b.app` 域名，无境内节点记录）

### 活跃度

- 该品类头部项目，融资状况良好，SDK 更新频繁
- 近期大动作：与 Anthropic 等合作紧密（Claude Code 沙箱场景常用 E2B）
- GitHub e2b-dev/E2B 持续有 release（截至调研日活跃）

## 2. Daytona

**定位**：面向 AI 生成代码的安全执行基础设施（daytona.io），从本地 dev environment 工具转型为 AI 沙箱平台。

### 免费额度（截至 2026-08-24，来源：daytona.io/pricing 及第三方核验）

- 注册送 **$200 免费 compute credits（一次性，非每月）**，无需信用卡，前 5 GiB 存储免费
- 定价：vCPU $0.0504/h、内存 $0.0162/GiB/h、存储 $0.000108/GiB/h；Windows 沙箱 $0.0858/vCPU/h
- 免费 credits **不可用于 GPU 沙箱**
- Tier 1（新账户）资源上限：10 vCPU、30 GiB 存储（内存上限文档内两表不一致：10 GiB / 20 GiB）
- credits 是否有有效期：官方未公开说明（**待验证**）

按 1 vCPU + 1 GiB 约 $0.067/h 估算，$200 ≈ **约 3000 沙箱小时**，教学场景非常充裕。

### SSH 支持（来源：daytona.io/docs/en/ssh-access）

**原生支持，是候选里 SSH 体验最好的**：

- token 认证（默认 60 分钟过期，可自定义）
- Dashboard / CLI（`daytona ssh --expires 60`）/ REST API 三种方式创建 SSH token
- 连接形式：`ssh <token>@ssh.app.daytona.io`，标准 SSH 服务器，支持 VS Code Remote SSH、JetBrains Gateway
- 与自研方案（SSH 端口）形态高度对齐，仅认证方式从「端口直连」换成「token + 网关」

### 语言运行时

- 沙箱可选镜像（含官方预置 + 自定义 Docker 镜像），Linux 与 Windows 均支持
- Container / VM / GPU 三种沙箱形态（VM 形态即 Firecracker 微 VM，隔离更强）

### 启动延迟

- 官方宣传「milliseconds」级启动（**待实测验证**）

### API 形态

- REST API + 官方 SDK（**TypeScript / Python**）+ CLI（`daytona`）
- 接口形状：create → start/stop/pause → execute（code run / process exec）→ upload/download files → delete
- 支持快照（snapshot）与暂停（pause）

### 开源与自托管

- **开源**（github.com/daytonaio/daytona，Apache-2.0），含 Open Source Deployment 文档（oss-deployment）
- 官方托管云与开源版并存；自托管可行（这正是它从本地 dev tools 转型而来的积累）

### 生命周期

- 按 sandbox 状态计费：Started 全额 / Stopped 只收磁盘 / Paused 只收磁盘 / Archived 不计费
- 详见官方 billing 文档的状态机表

### 地域与网络

- 官方未明确列出可选地域；**国内直连待验证**（`app.daytona.io`，无境内节点记录）

### 活跃度

- GitHub 活跃，2024-2025 转型 AI 沙箱后迭代快
- 商业化持续（startup 计划最高 $50k credits）

## 3. Modal

**定位**：serverless 计算平台（modal.com），不是传统「沙箱」，而是**函数级云执行**：把 Python/Node 函数部署为容器化函数，按毫秒计费。对「跑一段代码」的场景是同一需求的另一种形态。

### 免费额度（截至 2026-05，来源：modal.com/pricing 及多方核验）

- Starter 计划：$0/月，**每月 $30 免费 compute credits（每月续发，这是名单里唯一「按月续」的大额免费额度）**
- 附带限制：最多 3 个 workspace 席位、100 容器并发、10 GPU 并发、有限的 crons 与 web endpoints、1 天日志保留
- credits 可覆盖 GPU（不显式排除）
- 需要注册，信用卡非强制（**待验证**当前注册门槛）

$30/月 ≈ 按 $0.032/vCPU-h（大致量级）数百小时 CPU 执行，对每周几十次代码练习的学习者足够。

### SSH 支持

**无裸 SSH**。Modal 的模型是 `modal run`（本地 CLI）或 `Function.call()`（SDK/HTTP 调用），没有「登录进容器开 shell」的一等公民接口。与自研 SSH 方案形态差异最大，但 exec 语义完全覆盖「跑一段代码」需求。

### 语言运行时

- 原生 **Python** 为主，Node.js/TypeScript 支持（`modal.Function` 定义镜像）
- 任意 Docker 镜像可作 base image，完全自定义环境

### 启动延迟

- 冷启动取决于镜像：同容器连续调用毫秒级（微挂起/恢复），新镜像冷启动为「拉镜像 + 启动」级别（通常数百 ms 至数秒）

### API 形态

- 官方 SDK：**Python、TypeScript**；CLI：`modal run/deploy`
- 接口形状：定义 `@app.function` → `modal deploy` → HTTP endpoint 或 `function.remote()` 调用；文件系统有 `modal.CloudBucketMount` / `modal.Dict` 等原语
- 无「长驻沙箱」概念，执行粒度是「函数调用」

### 开源与自托管

- **modal-client（SDK）开源**（github.com/modal-labs/modal-client），**平台闭源、无自托管**

### 生命周期

- 函数级：调用即起、完成即挂起，自动缩放至 0
- 长驻 container（`modal serve` / interactive）也可，但计费持续

### 地域与网络

- 可选区域（Starter 即支持 region selection），有美国/欧洲节点
- **国内直连待验证**（`modal.com`/`*.modal.run`）

### 活跃度

- 非常活跃，融资充足（2025 年大额融资），版本迭代快
- 是 AI 代码执行（如 OpenAI、Anthropic 内部工具链）常用的执行底座之一

## 4. CodeSandbox SDK

**定位**：codesandbox.io 的沙箱产品线，2025 年被 **Together AI 收购**后主打「给生成式 AI 的 code interpretation」SDK（beta）。

### 免费额度（截至 2026-09，来源：codesandbox.io/pricing）

- 免费注册可用，Browser & VM Sandboxes 无限量创建（Build 计划）
- **VM Sandboxes 按 VM credits 计费**：$0.015/credit（1 credit ≈ 1 小时 VM 运行）

### SSH 支持

- 无裸 SSH。SDK 提供 `sandbox.commands.run()`（进程执行）、文件读写、端口预览（browser 沙箱可嵌 iframe）

### 启动延迟

- 官方宣传 **~150ms** 级（微 VM 按需冷启动；**待实测验证**）

### API 形态

- REST + 官方 SDK（**TypeScript / Python**，docs.codesandbox.io/sdk）
- 接口形状：`sdk.sandbox.create()` → `sandbox.commands.run / fs.write` → `sandbox.kill()`，模板（template）预构建

### 开源与自托管

- 闭源（部分前端/客户端组件开源，如 codesandbox 内核部分），无自托管

### 生命周期

- 沙箱自动休眠；免费层并发 10 VM
- 详细空闲回收策略**待验证**

### 地域与网络

- 官方未列明地域；**国内直连待验证**

### 活跃度

## 5. Morph Cloud

**定位**：Morph Labs（morph.so / cloud.morph.so）的 AI 云沙箱，核心卖点**秒级快照/回滚**（对 agent 迭代代码、失败重试非常友好）。

### 免费额度（截至 2026-09，来源：cloud.morph.so/docs/documentation/setup/plans）

- **Developer 计划：$0/月（100% 折扣）+ 起始 300 MCUs 免费 credits**
- 资源上限：最高 64 vCPU / 256 GB RAM / 1024 GB 存储（单实例可到 8 vCPU/8GB 常规配置）
- MCU 计价与「一次性还是每月」**待验证**（页面写「Starting credit allocation」，看起来是一次性起始额度）
- Team $40/月 1000 MCUs，Enterprise $250/月 7500 MCUs

### SSH 支持（来源：cloud.morph.so/docs/documentation/instances/ssh）

**原生支持**，且设计比较完善：

- 托管 SSH 公钥（在账户设置中登记），`ssh <instance-id>@<gateway>` 直连，支持交互与非交互会话
- 也可用 SDK/CLI、或临时生成的实例凭据（可分享给他人、无需 API key）
- 支持 SFTP 文件传输
- 与自研方案形态对齐度高（标准 SSH 网关 + 实例 ID 即用户名）

### 语言运行时

- 沙箱即完整 VM（MorphVM），任意镜像/快照可引导
- 快照机制：把「文件系统 + 进程内存」整状态存档、秒级恢复——agent 教学场景可以「回到出错前」重跑

### 启动延迟

- 官方称部署秒级；快照恢复**亚秒级**（**待实测验证**）

### API 形态

- REST + SDK（**Python 为主，TypeScript 亦有**）+ CLI（morphcloud CLI）
- 接口形状：`sandbox.start()` → `command.run` / `fs` → snapshot / `sandbox.stop()`

### 开源与自托管

- SDK 开源（github.com/morph-labs/morphcloud-sdk），平台闭源

### 生命周期

- 实例持续运行则持续计费；快照保留与回收策略**待验证**

### 地域与网络

- **国内直连待验证**（`cloud.morph.so`）

### 活跃度

- 较活跃（AI 沙箱新玩家，GitHub SDK 持续更新）；规模小于 E2B/Daytona

## 6. Judge0

### 免费额度（截至 2026-09，来源：rapidapi.com/judge0-official/api/judge0-ce/pricing）

- 隐性限制：执行有 CPU/时间上限，submissions 有排队，不适合长驻环境

### SSH 支持

**无**。纯「提交源码 → 返回编译/运行输出」的一次性判题 API，无交互环境。

### 语言运行时

- 支持 **60+ 语言**（主流 OJ 语言全覆盖），版本可在请求中指定

### 开源与自托管

### 生命周期

- 无沙箱生命周期概念（每次执行即焚）

### 地域与网络

- RapidAPI 网关国内访问不稳定（**待验证**）；自营版地域待验证；自托管无此问题

## 7. Piston

## 统一封装建议

自研 docker+ssh 与各家云沙箱要做成同一套接口给 agent 用。以下按「接口形状 → SSH/exec 弥合 → 推荐 → 淘汰 → 切换设计」展开。

### 1. 公共接口形状

所有候选（含自研）的生命周期都可归约为同一形状：

```
create(template/image, resources, ttl) → { id }
  ├─ upload(files)                     # 可选
  ├─ exec(command, stdin?, timeout) → { exitCode, stdout, stderr }
  ├─ download(files)                    # 可选
  ├─ [pause / snapshot / resume]       # 可选优化项，部分后端支持
  └─ stop / destroy
```

后端分两类，统一接口都要覆盖：

| 类别 | 成员 | 特征 |
| --- | --- | --- |
| **会话型**（有环境生命周期） | 自研 docker+ssh、E2B、Daytona、Morph、Vercel Sandbox、GitHub Codespaces、CodeSandbox | 完整五操作；可保持状态跨多次 exec |
| **即焚型**（无环境概念） | Judge0、Piston、JDoodle、Modal（函数粒度） | 单次调用即完成「create+upload+exec+destroy」 |

即焚型的适配：统一接口的 `runCode(lang, source, stdin)` 在即焚后端是一步 HTTP；会话型后端由适配器编排为 create → 写文件 → exec → destroy。反向对即焚型**不虚构**会话能力（capability 里标 `persistentFiles: false`），上层按能力降级。

### 2. SSH 型与 exec 型的弥合

核心洞察：**agent 需要的不是 SSH 协议本身，而是「低延迟、可交互地在隔离环境里跑命令」**。SSH 只是自研方案的实现载体。因此弥合方向不是「给 exec 型补 SSH」，而是把命令面统一到 exec 语义，SSH 降级为后端实现细节：

**统一 CLI 命令面（8 个命令覆盖全部候选）：**

```bash
sandbox create    [--template <name>] [--ttl <min>]   # → sandbox id
sandbox exec      <id> -- <command...>                 # 一次性执行
sandbox run-code  <id> --lang <lang> [--file <path>] [--stdin <file>] [--timeout <s>]
sandbox upload    <id> <local-path> <remote-path>
sandbox download  <id> <remote-path> <local-path>
sandbox list / sandbox info <id>
sandbox stop      <id>
sandbox destroy   <id>
```

**同一命令面在两类后端的实现映射：**

| 命令 | 自研 docker+ssh（SSH 型） | exec 型云沙箱 |
| --- | --- | --- |
| create | `docker run -d -p <port> …`（起 SSH 容器） | SDK `Sandbox.create()` |
| exec | `ssh -p <port> user@host -- <cmd>` | `commands.run()` / `runCommand()` |
| upload | `scp -P <port>` | 各家 files API（Vercel 是 node:fs 兼容） |
| stop/destroy | `docker stop / rm` | `kill()` / `destroy()` |

**三条设计原则：**

1. **能力协商（capabilities）而非接口分支**：每个后端声明 `ssh`、`interactive`（PTY）、`snapshot`、`customImage`、`languages[]`、`maxSessionMin`、`persistentFiles`。上层按能力降级——无 interactive 拒绝交互式教学流程、无 snapshot 用「文件落盘+重建」替代。**SSH 有无不作为接口分支条件，只作为能力标记**，自研与云沙箱在 agent 眼里完全同构
2. **文件操作独立成命令**：不鼓励「cat 管道过 exec」传文件；SSH 型后端走 scp/sftp，exec 型走 files API，两边都干净
3. **id 带后端前缀**（`daytona:abc123`、`local:docker-4f2`），天然支持多后端并存与追溯

交互式会话（PTY）特殊处理：教学偶有需要（REPL、交互式 stdin 程序）。Daytona/E2B 有 PTY API，自研直接 `ssh -t`，纯 exec 型用「多次 exec + stdin 文件」模拟——能力标记驱动上层选择策略。

### 3. 推荐：最值得接入的 2–3 个

**教学负载基线**（重度学习者）：每天 20–50 次执行、每次 5–30 秒环境时间 → **每月约 3–10 沙箱小时**。

**主推荐（按优先序）：**

1. **Daytona —— 综合最优**
   - 免费 $200 一次性 ≈ 数千沙箱小时（1 vCPU + 1 GiB ≈ $0.067/h），按基线够用数年
   - **候选里唯一「原生 SSH + REST exec 双通道」**：token + 网关的 SSH 与自研「SSH 端口」形态最贴，又能纯 API 接入——SSH/exec 两类形态的弥合成本最低
   - **开源 + 可自托管**：credits 耗尽可迁自托管（同一套 SDK 语义），不锁死
   - TS/Python SDK + CLI 齐全；sub-90ms 启动
   - 风险：一次性 credits 不续发；默认容器级隔离（跑不可信学生代码可选 Kata microVM 档）
2. **E2B —— 生态与体验标杆**
   - 免费 $100 一次性 ≈ 约 2000 沙箱小时，够 1–2 年
   - ~80ms 快照启动 + 任意 Docker 镜像模板：**「课程预置环境秒开」体验最好**，对多语言教学（预装各语言运行时的模板）价值大
   - SSH 可模板补装（openssh-server + websocat，官方文档有方案），能对齐自研形态
   - Firecracker microVM 隔离强；TS/Python SDK；文档与社区最好
   - 风险：一次性 credits；Hobby 单沙箱 1 小时上限（教学无碍）
3. **Vercel Sandbox —— 唯一「每月续发」的 microVM 免费层 + 技术栈零摩擦**
   - Hobby 每月 5 active CPU-h + 420 GB-h 内存**每月续发**，长期使用不枯竭（按基线刚好覆盖，紧但可行）
   - **官方 SDK 就是 Node.js/TypeScript**，pi-teacher 纯 TS 项目接入零语言摩擦，FileSystem 是 `node:fs/promises` 兼容
   - Firecracker microVM，隔离同 E2B 档
   - 风险：无 SSH（走能力协商的 exec 路线）；45 分钟会话上限；本月超额即暂停

**Morph Cloud 列为第 4 备选**：一次性 300 MCUs + 原生 SSH + 秒级快照分支都不差，但免费层「一次性还是每月」待验证、体量小于前三，先观察。

**场景化备选**：Modal（$30/月每月续、函数型）——若产品形态收敛为纯「算法题判题」（只 runCode、不需环境交互），它是每月续发最稳的，但与自研 SSH 方案形态差异最大；GitHub Codespaces（120 core-h/月每月续 + 原生 SSH + devcontainer）——额度与形态都好，但程序化只能走 gh CLI、冷启动数十秒、国内网络需代理，适合用户本就有 GitHub 习惯的场景。

### 4. 不值得接入的候选

| 候选 | 一句话原因 |
| --- | --- |
| Fly.io Machines | 2024-10 起对新客户**无任何免费额度**，起步绑卡付费；形态好但「免费」维度出局 |
| Cloudflare Workers/Containers | Containers 无免费层（需 Workers Paid $5/月，本次已核验）；Workers 语言面窄（JS 为主、Python 实验受限、10ms CPU）；无交互环境，为 HTTP 服务设计 |
| Replit | 无程序化执行 API、无 SSH、环境不可自定义——面向人类 IDE 用户，不是 agent 沙箱 |
| Ona（原 Gitpod Flex） | 免费层仅一次性 $10 = 40 OCU（第三方实测数天耗尽）；品牌/产品剧烈变动；程序化 API 弱 |
| JDoodle API | 免费 20 credits/天 ≈ 20 次执行，重度学习者明显不够；无自托管出路 |
| Runloop | 免费仅 $50 试用性质；Pro $250/月地板价远超个人预算 |
| Judge0 / Piston 公共托管版 | Judge0 RapidAPI 免费档额度小且网关国内访问不稳；Piston 公共实例 2026-02-15 起停止免费开放 |
| OpenComputer 云服务 | 无免费额度（$0.24/h）；其开源实现另作自托管参考 |

**重要保留**：Judge0 与 Piston 的**开源自托管**不在淘汰之列——若有一台国内 VPS，两者都是一键起、网络零依赖的判题兜底，可与自研 docker+ssh 并列（自研管「环境型」教学，Piston/Judge0 管「判题型」执行）。

### 5. 多后端切换设计：配置显式切换，不做自动 fallback

**倾向：显式配置切换。** 理由：

1. 单用户产品、执行低频，可用性损失可接受；自动 fallback 的复杂度（状态漂移、故障归因、计费追踪）远超收益
2. **一个会话跨后端 = 环境不互通**：前半节课的文件在后端 A，切到 B 就丢，学习者与 agent 都会困惑——fallback 制造的坑比它填的多
3. 违背「约定优于配置」：自动调度器是独立的基础设施，需要自己的测试面与运维关注

具体建议：

- 配置指定 `activeBackend` + 后端清单（各自 key）；切换是显式动作（界面或配置一行）
- create 失败（额度耗尽/网络不可达/超限）返回**结构化错误 + 建议**（如「Vercel 本月额度已尽，可切换 Daytona」），决策交给人或 agent 上层逻辑，适配器不偷偷切
- 静态优先级建议：**一次性 credits（Daytona/E2B）用于重度课程实验；每月续发（Vercel/Modal）做长尾日常；自研 docker+ssh 恒为默认与离线兜底**
- 未来开放多用户再考虑额度感知调度，首版不做

### 6. 与 ADR-0015 / ADR-0027 的衔接

- 这层抽象做成 **TypeScript 库**（与主应用同栈）+ 对外暴露上述 8 命令 CLI；载体（skill 教 agent 用 CLI，还是插件 `defineTool` 直接调库）**待后续拍板**——两种载体共用同一套库/CLI，换载体不动后端
- 主镜像仍只有 Node.js 一个运行时：所有语言运行时在沙箱端，与 ADR-0015 一致
- 判题形态（即焚型后端：Modal/自托管 Piston）与环境形态（会话型后端）在统一接口下并存，按教学场景选型
