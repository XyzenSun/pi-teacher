# Pi Teacher

一个 Web 学习助手。它通过多种学习风格帮助用户理解知识、练习知识，并让值得长期保持的知识真正留下来。

本文只定义领域语言，不记录实现方案、技术选型或字段设计。Schema 见 `数据库与目录结构设计.md`。

## Language

### 容器与对话

**Space（收纳容器）**：
收纳若干次 Pi Session 的数据库实体，同时用 `type` 标记活动类型：`learn`、`review` 或 `ta`。Space 只负责聚类，不拥有 Pi 的工作目录，也不提供跨 Pi Session 的文件上下文。学习 Space 可由用户创建；复习 Space 全局唯一；助教 Space 全局唯一。
_Avoid_: 学习空间、StudySpace、Workspace、Session Group、会话组、项目

**Pi Session（对话）**：
一次完整的多轮对话，归属于某个 Space，并拥有独立的工作目录与对话历史。开始时选定提示词模板与教学风格；提示词模板之后不变，教学风格可在对话进行中切换。名称由 AI 在首轮结束后生成，是 AI 唯一有权命名的东西。助教是全局唯一的固定 Pi Session，不提供创建入口；从任何位置打开助教都复用它。
_Avoid_: 会话、conversation、chat、thread

**Space Type（容器类型）**：
Space 的固定活动类型：`learn` 表示围绕资料教学，`review` 表示围绕全局卡片复习，`ta` 表示答疑助教。Pi Session 通过所属 Space 继承类型；类型不是可由用户随意新增的实体。
_Avoid_: 模式、学习模式、复习模式

**Turn（轮次）**：
对话中一次「用户发言 + 助手回应」的来回。周期性提醒以轮次计数。
_Avoid_: 消息、message、round

### 提示词

**Agents Md（提示词模板）**：
决定一次对话「做什么」的提示词——新学、新学不制卡、复习、助教等。用户可自定义，在开对话时选定。
_Avoid_: 系统提示词、system prompt、mode

**Teach Style（教学风格）**：
决定一次对话「怎么说话」的提示词——循序渐进的老师、苏格拉底式追问等。与提示词模板正交，可自由组合。用户可自定义。开对话时选定，也可在对话进行中切换：切换后对话以新风格重新载入，历史与已选模型保留（ADR-0031）。
_Avoid_: 人格、角色、persona

**Global User Preferences（全局用户偏好）**：
用户写给老师的长期偏好，存于 `~/pi-teacher/USER.md`，可在系统设置里编辑。开对话时与 Teach Style 一起注入，优先级低于 Teach Style 与会话级用户偏好。
_Avoid_: 用户画像、profile、memory

**Session User Preferences（会话级用户偏好）**：
用户只针对本次对话提出的要求，由 AI 在对话中记录到该 Pi Session 目录下的 `pi-session-user.md`。程序不读不写，只告诉 AI 它的存在与优先级：高于 Teach Style 与全局用户偏好。
_Avoid_: 会话 USER.md、临时偏好、session memory

**Briefing（上下文注入）**：
向模型注入的当前状态。静态部分（提示词模板、教学风格）在开对话时投影为文件；动态部分（待复习卡片数、学习进度）在每轮请求前注入，不进对话历史，不受压缩影响。
_Avoid_: 系统提示词、上下文窗口、历史摘要

**Reminder（提醒）**：
每隔固定轮次（`reminder_interval_turns`，默认 30，0 关闭全部提醒）拼在用户消息末尾的 `<system-reminder>`，让模型考虑是否维护偏好、用户信息、卡片或会话级要求。三段基础文案按「学习 / 复习 × 制卡开关」与「助教」选取；仅学习 Pi Session 同轮再追加学习精华提醒，无论制卡开或关（ADR-0036 / ADR-0039）。提醒随用户消息落 JSONL，历史里可见。接收者是模型，不是用户；界面不因此弹窗，是否实际维护由模型判断。
_Avoid_: 通知、prompt、催促

### Pi Session 产出

以下全部是当前 Pi Session `work_path` 下的文件，模型读写，不进数据库；Space 只负责收纳，不提供这些文件的共享目录。

**Mission（使命）**：
当前 Pi Session 工作目录中的文件，讲解为什么要学这个知识、要掌握到什么程度。它为本次对话提供学习方向；跨 Pi Session 复用的资料应放入全局 Material。
_Avoid_: 学习目标、目标、goal

**Glossary（术语表）**：
当前 Pi Session 工作目录中的标准语言文件。当前对话的讲解、练习和学习记录遵循其中的术语。能把一个概念压缩成简明定义，正是用户已经理解它的证明。
_Avoid_: 词汇表、名词解释

**Mastered Term（已掌握术语）**：
用户已彻底搞懂的术语，从当前 Pi Session 的术语表沉淀进数据库，全局有效、跨 Space 共享，不归属任何 Space 或 Topic。它让 AI 知道用户的知识底座，从而跳过已懂的、直接讲新的。门槛比术语表高得多：术语表记的是「本次对话中约定了口径」，已掌握术语记的是「这个人真的会了」。入库需用户确认。内容不注入上下文，由 AI 自行决定何时查询。
_Avoid_: 全局术语表、知识点、掌握清单

**Learning Record（学习记录）**：
当前 Pi Session 工作目录中按顺序编号的学习进度记录，只给 AI 看，用户不会翻。它存在的理由是对话上下文会丢。
_Avoid_: 日志、笔记、历史

**Essence（精华）**：
学习 Pi Session 产出的、用户以后真正会反复查阅的内容。它是课程内容的精炼，要美观、结合图片、便于快速查阅，是独立于卡片的学习产出（ADR-0039）。程序只为学习 Pi Session 默认提供空的 `essence/`，内容由模型按需维护；卡片不保存精华路径。助教与复习不自动创建精华目录或追加精华维护提醒，已有文件仍保留。
_Avoid_: 笔记、总结、文档

**Material（资料）**：
用户提供或从互联网获取、经模型判断正确且具备可学习性的资源，存于全局 `materials/`，优先保留高质量内容。规整资料直接归档；内容组织或排版混乱的，原件保留在 `materials/origins/`，整理后的学习版本放入资料库。阅读判断、整理、移动和 `materials/index.md` 维护均由模型执行，程序不代办；不擅自删除用户文件（ADR-0039）。
_Avoid_: 文件、附件、素材

**Session Files（会话文件）**：
用户上传给当前 Pi Session 的原始文件，落在该对话工作目录的 `files/` 下（ADR-0038）。它们是待阅读、待判断的输入，不等于已合格的 Material；模型按 ADR-0039 的资料规范判断、整理并归档到全局资料库。图片作为图片块随消息进入对话，其他文件只把路径与大小告诉模型，后端不做内容转换或自动归档。「附件」指上传这个动作（HTTP 路由名），不是文件的归属。
_Avoid_: 附件目录、attachments/

### 卡片与复习

**Card（卡片）**：
一个值得长期保持的知识单元。正面是问题，背面是参考答案或评价标准，另附 AI 写的制卡原因与补充说明。归属于 Topic，不归属于产出它的对话。它既是复习的核心，也是记录用户已学内容的载体。八股问答、背单词、算法题共用同一种形态，评价方式交给 AI 判断。
_Avoid_: 题目、知识点、flashcard、错题、难题

**Card Proposal（卡片提议）**：
模型提出的、尚未经用户确认的候选卡片。未经确认的提议不参与复习计划。
_Avoid_: 候选卡、草稿卡、自动卡

**Topic（主题）**：
卡片的归属维度，也是复习调度参数的配置粒度。可以细化到任意粒度，例如「后端」「Java」「JVM」，制卡时 AI 优先复用现有主题。
_Avoid_: 分类、标签、类别、领域

**Rating（评级）**：
一次复习的结构化结论，取 `Again / Hard / Good / Easy` 四档，由 AI 判定。它是模型评价与调度计算之间唯一的接口。
_Avoid_: 得分、评分、grade

**Review（复习）**：
针对某张卡片的一次作答与评价。只有评级入库，评语是给用户看的一次性反馈。
_Avoid_: 测验、考试、答题

**Due Queue（到期队列）**：
某一天应当复习的卡片集合。由调度状态确定性地算出，不由模型挑选。
_Avoid_: 今日任务、复习列表

### 用户模型

**Preference（偏好）**：
用户对讲解方式的稳定要求，例如表达风格、类比禁忌、代码示例习惯。以用户手写为主，写在全局或工作区级的用户文件里。
_Avoid_: 设置、配置、画像

用户模型有两块，互补而不重叠：偏好是「希望怎么被教」，已掌握术语是「已经会了什么」。前者在全局或当前 Pi Session 的文件里由用户手写，后者在数据库里由 AI 提议、用户确认。
