
session相当于学习工作区，之所以不叫 studyspace， 主要是为了 复用 pi的 session概念。
## 目录

```
~/pi-teacher/
  ├─ AGENTS.md              ← 全局规则，含资料库的使用说明
  |- USER.md                重要! 关于用户，用户的基本信息：专业，年龄，用户偏好
  ├─ materials/             ← 全局资料库,应当全部以可读的形式存储，例如markdown，html，图片，像pdf这种ai不可直接识别的内容，存储到origins子目录，表示原件，而 materials 存储转换后的，像包含图片的html，可以以文件夹的形式存储， 如 about-docker/index.html css ,imgs ，如果是一系列课程，比如用户指定了一个几十集的bilibili的视频，应该存储为 课程名文件夹/lesson1-本节内容-本节内容简要标题.md lesson2-本节内容简要标题.md lesson3-本节内容简要标题.md ，需要定期维护，毫不留情地删减。那些被证明错误、肤浅或偏离目标的资源，应当移除而非埋没。五个精辟的来源胜过三十个平庸的。只信任高可信度的来源。优先选择原始资料、权威专家、经过同行评审的作品以及有严格审核的社区
  │   ├─ index.md 索引文件
  │   ├─ java-concurrency.pdf
  │   └─ bilibili-BV1xx.md
  |- assest/ 命名一定要见名知意，这个文件夹内内容不会太多，所有无需索引，样式表、测验小部件、模拟器、图表辅助工具，以及任何其他课程能复用的内容，重点是，其他课程能复用，比如用户明确说这个html页面的风格不错，那么这个html就可以作为模板存入这里。  此目录必须保持精华。
  ├─ learn/
  │   └─ 5/ 此id对应数据库表session中的id
  │       ├─ AGENTS.md      ← 此会话中的学习风格+用户对此会话的特殊要求(从数据库读取)
          --/essence - /name1.html name2.html    - 用户以后真正会去看的东西，那些用户真正会反复查阅的内容，要制作的美观，结合图片，让学习者“一图胜前言的理解并记忆”，课程内容很少会被反复回顾，但参考文档会被。它们应该是课程内容的精炼精华，并且要以方便快速查阅的格式呈现，如果要制卡复习，这也将是制卡的资料来源，卡片应该是凝结的精华。 
          -- assest/存放生成的图片、css资源等，命名一定要见名知意，这个文件夹内内容不会太多，所有无需索引，不需要考虑被其他学习会话复用。
          |- MISSION.md  记录为什么要学习这个知识，包括对此知识的掌握程度需求。使命（你希望掌握这项技能的具体现实原因）为每节课提供了根基；没有使命，课程就会变得抽象，无法决定下一步该学什么。基于使命和学习记录， 既要有足够的挑战性让你付出努力，又不能太过超前，导致无法掌握。，这是学习体系最重要的东西，必须为此用大量努力确保他的高质量，就像卡片是复习的核心一样。
          | GLOSSARY.md 是此教学工作区的标准语言。所有解释、练习和学习记录都应遵循其术语。构建它本身也是学习的一部分：把概念压缩成简洁的定义，说明用户已经理解了它。
          | learning-records / 此目录用于记录学习进度，用户不会去看这个目录，只给ai看。采用顺序编号： 0001-slug.md 、 0002-slug.md 等
          | GLOSSARY.md  此学习会话的所有讲解、练习和学习记录都应遵循其中的术语。构建词汇表本身就是学习的一部分：能把一个概念压缩成简明的定义，正是用户已经理解它的证明。
  │       └─ *.jsonl
```
