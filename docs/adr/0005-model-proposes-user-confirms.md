# 模型只能提议，写入需用户确认

卡片和偏好都会长期影响学习体验：错误的卡片会被反复复习，错误的偏好会持续扭曲讲解风格。因此模型不能直接把它们写进业务库，只能提出提议，由用户确认后才生效。偏好尤其以用户手写为主，模型提议是补充而非主要来源。

## Consequences

- 未经确认的提议不参与复习计划，也不影响讲解行为。
- 长对话可能积累大量卡片提议，需要限流与去重，避免「卡片洪水」淹没确认界面。
- 提议与确认都要走结构化工具调用，不依赖从自然语言里解析模型意图。
- 周期性提醒只是让模型「考虑是否需要维护」，不是要求它每次都产出提议；没有值得更新的内容时，模型不需要在回复里汇报这次检查。
