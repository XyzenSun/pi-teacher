# 资料归档由模型分流，学习精华独立于卡片

- 状态：已采纳
- 日期：2026-09-11
- 相关：ADR-0010（卡片职责边界）、ADR-0016（资料获取）、ADR-0029（用户资源目录）、ADR-0033（提示词来源）、ADR-0036（维护提醒）、ADR-0038（会话 `files/`）
- supersedes：ADR-0010 的 `source_essence_path` 引用；ADR-0036 只有三段提醒文案的范围；ADR-0038 第 1 条笼统的资料归档说明。其他职责与接口保持不变。

## 背景

上传文件已落在会话 `files/`，但旧全局提示词只要求把新资料放进 `materials/origins/`，没有区分合格资料与待整理原件。用户上传的内容可能来自零散复制，需要模型先判断正确性和可学习性，再决定是否整理归档，不能由程序无条件搬移。

`essence/` 原本只有全局提示词中的一句目录约定，没有默认目录，也没有周期性维护提醒。卡片仍保存可空的 `source_essence_path`，而前端没有实际消费对应来源标记。用户决定简化这层关系：精华是独立学习产出，卡片不再记录精华路径。

## 决策

### 1. `files/` 是待判断输入，`materials/` 是全局学习资料库

上传接口与 ADR-0038 一致，只把字节保存到当前会话 `files/`。全局 `AGENTS.md` 的出厂模板 `GLOBAL_AGENTS_MD` 规定：

1. 模型先实际阅读，判断资料是否正确、具备可学习性。不能确认的，不直接归档为正式学习资料，并说明不确定之处。
2. 确认正确且可学习，内容与排版规整：直接移入全局 `materials/`。
3. 确认正确且可学习，但内容组织或排版混乱：原件先移入 `materials/origins/` 保留，整理后的可学习版本存入 `materials/`。
4. 模型维护 `materials/index.md`，记录学习版本路径与简短说明；有原件时标明对应路径，避免把未整理原件当成正式版本。
5. 不擅自删除用户文件，不覆盖已有资料。阅读判断、移动、整理与索引维护都由模型执行。

后端不新增自动归档、质量判断、内容转换或索引维护服务。这是提示词约束，不是后台流水线。

### 2. 仅学习 Pi Session 默认提供 `essence/`

- `session/repository.ts` 集中定义 `SESSION_ESSENCE_DIR_NAME` 与 `ensureLearningEssenceDirectory()`。只有 `learn` 会话创建 `<work_path>/essence/` 空目录，程序不写精华正文。
- 新建时复用现有事务与目录回滚边界；旧学习会话在正常 `openConversation()`、确认原 JSONL 存在后幂等补建。不启动全盘扫描，不创建替代会话。
- 助教、复习不会自动创建精华目录；任何类型会话已有的精华文件都保留，不删除、不覆盖。
- 学习会话的 `essence` 路径被普通文件占用时明确返回 409，不把文件当成目录，也不替换它。
- 精华的选题、组织与维护由模型判断，仍可按需阅读其中的知识；移除路径关联不等于禁止模型参考精华。

### 3. 与基础提醒共用轮次，只对学习追加精华段

保留三段基础文案 `makeCardOn` / `makeCardOff` / `ta` 及其既有用户自定义内容，不改变出厂值。新增第四段 `learningEssence`，对应 `setting.reminder_text_learning_essence`：

- 出厂文案集中在 `prompts/defaults.ts` 的 `REMINDER_TEXT_DEFAULTS`；缺行取默认，PATCH 空串或纯空白删行恢复默认，长度沿用 4000 上限。
- 设置页复用 `ReminderTextField`，增加「学习精华」，不新增间隔或开关。
- 共用 `reminder_interval_turns`（默认 30，0 关闭全部提醒）与现有活动分支 user 消息计数，不增加计数器或定时任务。
- 命中时，先按类型和制卡开关取基础文案，再仅对 `spaceType === "learn"` 追加精华段，段间用空行分隔。学习制卡开、关都适用；复习与助教仍只有原基础文案。
- `prompt` / `steer` / `follow_up` 复用同一条拼接路径。提醒随用户消息落 JSONL，历史保持可见。
- 精华文案引导按需阅读、补充或修订已有内容，避免重复和流水账；是否更新及更新什么由模型决定，不要求每次命中都写文件。

精华段不能直接塞进学习 / 复习共用的基础文案，否则会错误提醒复习会话维护精华。

### 4. 卡片不保存精华路径

新库 `card` 不再有 `source_essence_path`。旧库在 `initializeSchema()` 建表后、seed 前，按既有删列迁移模式检测 `PRAGMA table_info(card)`，存在该列才执行 `ALTER TABLE card DROP COLUMN source_essence_path`。

同步移除 `card_propose` 参数、`card_get` 与复习取卡返回字段，以及 HTTP / 前端类型里的 `has_source_essence`。不新增替代字段、文件绑定或跳转接口。卡片其他字段、ID、自增序列、调度数据、复习日志与精华文件均保留。ADR-0030 对更早 `session` 表模型拒绝迁移的边界不变。

## 既有部署

- 全局 `~/pi-teacher/AGENTS.md` 是用户文件，seed 仍然只补缺失。升级后需要在「系统设置 → Agents Md → 全局 AGENTS.md」手工合并新资料规范与学习精华职责，不能由程序覆盖。
- 原三段自定义提醒无需重置；新增精华文案缺行即有默认值，在下一个学习命中轮生效。
- 容器需要重建镜像，不是只 restart。无需重建数据库或学习会话；升级前备份，回退旧版本时应同时恢复升级前的数据备份。

## 验证边界

使用真实临时 SQLite、真实目录与 Pi SDK / 模型。验证旧列幂等迁移及数据保留、学习专属目录、设置持久化、本轮对话请求中 user 消息的完整组合、历史可见性与工具契约。不把模型是否实际移动资料或写精华作为程序验收的硬断言。浏览器验收由用户负责。
