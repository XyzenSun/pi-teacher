# Topic 粒度宜细，并承载调度参数

Topic 既是卡片的分类维度，也是调度策略单元。这两个角色共同决定了它应当做细。

## 粒度宜细不宜粗

预置主题按细粒度给（例如「Java」「后端」「前端」「数学」「英语」），而不是「编程」这种大类。

理由是**不对称的**：跨主题复习有解，粗粒度没解。

- 想同时复习有交集的多个主题（例如「后端」与「Java」）——复习会话可以选多个主题，或不选任何主题即复习全部。
- 而一个已经堆满 Java 并发、React 渲染、数据库索引的「编程」主题，无法再被拆开。已产生的卡片和调度历史都已绑在它身上。

## Topic 承载 FSRS 参数

每个 Topic 持有自己的 `request_retention`（目标记忆保持率）与 `maximum_interval`（最长复习间隔）。`ts-fsrs` 支持这两个参数，其中 `maximum_interval` 正是「最长不超过 n 天」的表达方式——它给出间隔上界，同时保留「没掌握就更频繁」的下界自适应。

这样不同领域可以有不同的复习节奏：词汇类主题间隔上限设短（不用就退化快），概念类主题可以长。

FSRS 的间隔本身是算出来的，不能直接指定「每 n 天复习一次」——固定间隔等于关掉记忆模型。`learning_steps` / `relearning_steps` 确实是固定步长，但只作用于新卡初期与遗忘后的重学阶段。
