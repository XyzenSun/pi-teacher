# 会话文件目录 `files/`：图片直接进对话，其他文件只告诉模型路径，后端不做内容转换

- 状态：已采纳
- 日期：2026-09-10
- 相关：ADR-0016（资料获取交给 skill / 子代理）、ADR-0027（外部能力只走 skill 与插件）、ADR-0030（Pi Session 独占工作目录）、ADR-0033（`~/pi-teacher/materials/` 是全局资料库）
- supersedes：`open-questions.md` 中「附件保存到 `work_path/attachments/`」的对齐结论；`数据库与目录结构设计.md` 目录树里缺失的会话文件目录

> 状态补充（2026-09-11）：ADR-0039 细化第 1 条的资料归档规范——模型确认正确且可学习后，规整资料直接移入 `materials/`；凌乱资料的原件先入 `materials/origins/`，整理版本入 `materials/`，索引由模型维护。`files/` 目录、上传接口与路径注入形态不变。

## 背景

上传接口从一开始就接收任意类型（16MB 以内），落在 `work_path/attachments/`；发送时 png / jpeg / gif / webp 作为图片块直接喂模型，其余文件只在消息末尾的「本轮附件」列表里出现一行相对路径。前端却把选择框限制成 `accept="image/*"`，按钮叫「添加图片附件」，粘贴也只收图片——用户以为系统只支持图片，实际是前端拦住了。

设计阶段的目录树只有精华、学习记录等模型产出，从未给「用户上传给本会话的文件」留位置。用户后续要接视频理解、文档转 Markdown 这类 skill，这些 skill 的输入正是这些文件，因此目录与注入形态需要现在定下来。

## 决策

1. **目录定名 `<work_path>/files/`**，领域术语「Session Files（会话文件）」：用户上传给当前 Pi Session 的原始文件。与全局 `materials/` 的分界：`files/` 是本会话的输入，`materials/` 是跨会话的资料库；模型认为值得沉淀的，自己搬去 `materials/` 并维护索引。
2. **图片直接进对话**：png / jpeg / gif / webp 仍作为图片块随消息发送，不再在文本里列路径（模型看到的就是图，不需要再被告知文件在哪）。
3. **非图片只告诉模型路径**：命中的每个文件在用户消息末尾追加一行 `用户上传了文件「<文件名>」，路径 files/<文件名>（<大小>）。`。模型知道有文件、去哪读、多大，自己决定用什么工具读。
4. **后端不做任何内容转换**：不抽 PDF 文本、不转码视频、不解析 Office。这些是 skill 的职责（ADR-0016 / ADR-0027 的载体原则：模型自己决定是否用、失败了也无所谓的能力归 skill），上传服务只负责把字节安全地放到目录里。
5. **前端放开类型**：选择框不限 `accept`，粘贴收任意文件，文案改为「添加附件」；单次数量上限沿用后端的 8 个。
6. **HTTP 路由与模块名保留 `attachments`**：`POST/GET /api/conversations/:id/attachments` 描述的是「上传」这个动作，改名只增加前后端同步成本，不增加清晰度。对外的相对路径统一变成 `files/<name>`。
7. **已有部署的 `attachments/` 目录一次性迁移**：启动时遍历 `pi_session.work_path`，`attachments/` 存在且 `files/` 不存在就 `rename`；两者都在则不动、只记日志。之后程序不再认识 `attachments/` 这个名字。

## 为什么不是别的

- **后端把 PDF / 视频先转成 Markdown 再注入**：转换器要装依赖（ADR-0015 镜像不装 Python）、要管失败、要决定转多少进上下文；而模型拿到路径后可以按需读一段、用 skill 转、或者只看目录名。转换是能力不是管道。否决。
- **所有文件都列路径（图片也列）**：图片块已经在消息里，再列一行是重复；模型要保存图片时可以自己在 `files/` 下找。否决。
- **用 `<pi-teacher-files>` 一类信封标签包住文件列表**：真模型会把信封标签复述进回答（`docs/spec.md` 已记录），一行自然语言就足够表达，不需要结构化标记。否决。
- **保留 `attachments/` 名字不改**：「attachment」是 HTTP 上传的视角，落盘后它们是会话的文件；目录名要与 `materials/`、`essence/` 这类模型日常打交道的名字同一层级、同一风格。改名一次、迁移一次。否决。
- **兼容读取两个目录**：兼容逻辑要永远留着，只为一次改名；单用户部署做一次 `rename` 就结束。否决。

## 后果

- 目录树新增 `files/`；`ATTACHMENTS_DIR_NAME`、`createPiSession`、`seed.ts` 建目录处、`verify:attachments`、`http-smoke` 相关断言同步改名。
- 大文件上限仍是 16MB（单个）/ 32MB（单次发送合计），视频类输入现阶段进不来；等视频理解 skill 立项时再决定上限与上传方式，本决策不预设。
- 模型对非图片文件的理解质量取决于它手头有什么工具：Pi 自带 `read` 能读文本类文件，PDF / Office / 视频在对应 skill 到位前只能告诉用户「暂时读不了」。这是预期行为，不是缺陷。
- `CONTEXT.md` 增加 Session Files 术语；「Material」条目里 `_Avoid_: 附件` 保持——附件是上传动作，不是资料。
