# 助教 Pi Session 常驻、不带教学风格、上下文可一键清除

- 状态：已采纳
- 日期：2026-09-10
- 相关：ADR-0024（会话注册表与空闲回收）、ADR-0030（Pi Session 独占工作目录）、ADR-0031（Teach Style 运行期切换）、ADR-0033（提示词四层来源）、ADR-0036（维护提醒）
- supersedes：`数据库与目录结构设计.md` 目录树里助教目录下的 `style.md`；`seed.ts` 为助教投影 `style.md` 的做法

## 背景

固定助教（`space_type = "ta"`，全局唯一一条）和学习 / 复习会话走同一套生命周期：`AgentSessionWrapper.resetIdleTimer()` 十分钟无活动就 `shutdown()`。学习会话被回收是合理的——用户可能几天不碰它；助教却是跨对话的入口，挂在每个页面的侧栏里，回收后用户下一次点开要等真实 SDK 会话重建，冷启动成本直接落在「顺手问一句」这个最轻的动作上。

助教在 MVP 期间还继承了学习会话的一整套装备：投影 `style.md`、系统提示里带教学风格块、被 ADR-0036 的维护提醒要求维护全局偏好与用户信息。用户的判断是：**助教的本意是解答疑惑，它的上下文与记忆不重要**，为它做风格投影、记忆维护是反模式，设计得越多离本意越远。

## 决策

1. **助教常驻**。`startWorkspaceSession` 增加 `resident` 选项，wrapper 对常驻会话不设空闲计时器；只有进程收到 SIGTERM / SIGINT 时随其他会话一起优雅关闭。学习 / 复习会话维持十分钟回收不变。回收策略按会话类型分流，不是全局关掉计时器。
2. **首次访问时打开，之后不再回收**，不在后端启动时打开。首次部署 `models.json` 可能还没有任何 provider，启动即开会话只会把「模型未配置」变成启动日志里的报错；前端侧栏挂载时本来就会打开助教，效果等价。
3. **`POST /:id/close` 对助教返回 400**。关闭对常驻会话没有意义，界面上助教也没有「关闭」。
4. **助教不投影 `style.md`**。`createPiSession` 与 `seed.ts` 按 `space_type` 跳过；已有的 `ta/pi/<id>/style.md` 在初始化时删除（它是程序投影，不是用户内容，删除不违反「seed 只补不覆盖」）。助教的系统提示只可能带全局 `USER.md`——读，但不提醒它维护（ADR-0036）。
5. **清除上下文 = 删掉历史文件重来**。`POST /api/conversations/:id/clear`（只允许助教）：停掉运行中的 wrapper，删除 `pi_session.path` 指向的 JSONL，用创建时的同一套逻辑生成新的空会话文件并更新 `path`，随即重新打开并常驻。`work_path` 及其中的 `pi-session-user.md`、`files/` 保留。不做标记、不做归档、不保留旧文件。

## 为什么不是别的

- **全局把空闲回收关掉**：学习会话可能几十条，每条都是一个真实 SDK 会话；回收是为它们设的，助教只有一条。否决。
- **助教也保留教学风格**：助教没有「怎么教」的问题，只有「答不答得准」；风格块只会让答疑绕弯。ADR-0031 的运行期切换对助教已经 403，投影文件是没人读的空壳。否决。
- **清除做成「标记 + 新 JSONL，旧文件归档」**：助教的历史没有复用价值，归档只是把垃圾换个目录放；用户明确要求「直接删除历史对话就可以，不用做标记之类的」。否决。
- **清除时也删 `pi-session-user.md`**：那是用户对助教提出的要求，清除的是对话不是要求；要改它用户可以直接告诉助教。否决。

## 后果

- 后端进程内始终多一条活着的 SDK 会话（助教），内存代价固定且只有一份。
- `verify:lifecycle` 要把「学习会话被回收、助教仍活着」当成断言的一部分；`http-smoke` 结尾的 `shutdownAllSessions()` 已覆盖常驻会话。
- 清除会让正在连接的 SSE 收到一次 `session_recycled`，前端在清除成功后重新打开即可，用户不感知重启。
- 真实部署目录里已有的 `ta/pi/1/style.md` 会在下一次启动被删除。
- `CLAUDE.md` 里「空闲会话 10 分钟回收」改为「学习 / 复习会话空闲 10 分钟回收；助教常驻」。
