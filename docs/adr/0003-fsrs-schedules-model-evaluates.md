# 调度由 FSRS 计算，模型只负责评价回答

复习日期必须可预测、可审计、可重算，这类确定性结论不能交给模型自由决定。我们采用 FSRS 作为调度基线（复用 `ts-fsrs`），并把职责切开：模型负责评价开放式回答的正确性、完整性与吃力程度，输出结构化 Rating；代码负责用 Rating 计算下一次到期时间与卡片状态。

## Considered Options

- **模型自由决定复习日期**：无法审计、无法重算，同一份回答两次给出的间隔可能不同。否决。
- **嵌入完整 Anki 或通过 AnkiConnect 依赖本地 Anki 进程**：为了一个调度算法引入整个应用和进程依赖，且无法在服务端无头运行。否决。
- **`ts-fsrs` + 自建评价层**：调度算法成熟且纯函数，评价层留给模型发挥。采纳。

## Consequences

- Rating 的四档不是百分制的线性映射：核心结论错误判 `Again`，答对但明显吃力才是 `Hard`。这条规则必须写进评价 rubric，否则模型会把 60 分映射成 `Hard`。
- 模型可以提出特殊调度覆写请求，但必须经过明确的工具与业务校验，不是默认路径。
- 复习记录需完整保留，以便日后分析乃至训练个性化参数。
