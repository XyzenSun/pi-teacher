# 彻底掌握的术语沉淀进数据库，成为全局用户模型

工作区的 `GLOSSARY.md` 只在本工作区有效——在 JS 工作区学会了「闭包」，开一个 Python 工作区，AI 又从零开始解释闭包。术语表是文件，散在各工作区里，无法汇总。

因此增加一张 `glossary` 表：**彻底搞懂**的术语连同用户自己的定义入库，全局有效。AI 在任何对话里都能知道「这个人已经会了什么」，从而跳过已懂的、直接讲新的。

## 两层结构，不是同一份数据的两处存储

`GLOSSARY.md` 与 `glossary` 表的门槛差一个量级：

- **文件**记的是「本次学习中用到了这个词，约定了口径」。它的作用是统一讲解、练习、学习记录的用词，避免同一个概念换三种说法。随学习推进频繁增改。
- **表**记的是「这个人真的会了」。它的作用是全局的知识底座。只增，很少改。

一个术语先进文件（约定口径），学明白之后才被提议进表（沉淀为能力）。**入库不从文件里删掉它**——本工作区仍然需要它作为标准语言。

这个分层是有意的：如果只有一层，要么门槛降到「用过就算会」（AI 会跳过用户其实没懂的东西），要么门槛升到「彻底懂才写进术语表」（术语表就失去了统一用词的作用，因为学习过程中大部分词都还没彻底懂）。

## 入库需用户确认

`status` 三档（`proposed` / `normal` / `deleted`）与 `card` 完全同构，理由也一样（见 ADR-0005）：错误的记录会**持续**扭曲讲解。AI 以为用户懂了「协变」，之后所有涉及泛型的讲解都跳过它，用户就一直不懂，而且不知道自己为什么听不明白。

这类错误比错误的卡片更隐蔽——错卡会在复习时暴露，错术语只会让讲解悄悄跳过一层。所以确认环节不能省。

## definition 存用户自己的话

入库时直接取工作区 `GLOSSARY.md` 里的那一条，不重写成教科书定义。ADR-0009 已经说过这个道理：能把概念压缩成一句简明定义，本身就是理解的证明。用规范的定义替换掉用户自己的说法，等于把证据换成了标准答案。

副作用是这些定义可以直接当卡片素材——已经是凝练的了。

## 表里不放任何外键

`glossary` 只有 `term`、`definition`、`status`、`created_at`。不挂 `topic_id`，不记 `source_path` 或 `session_id`。

这不是省字段，是守住这张表存在的理由。**只要出现一个指向工作区或主题的引用，它就从「用户会什么」退化成「某次学习的附属产物」**，而后者用工作区里的文件就能表达，不需要建表。

具体地：

- `topic_id` 会立刻引出「一个术语属于多个主题怎么办」。这个问题无解，说明主题不是术语该有的维度。同名不同义（「引用」在 C++ 和 Java 里不同）靠把术语写具体来解决——`C++ 引用`、`Java 引用`。
- `source_path` 看似无害的溯源，实际把全局资产绑回了临时容器：工作区删掉后字段悬空，而术语本身依然有效。而且这个需求不真实——用户想知道的是「我会不会」，不是「我在哪学的」。

代价是失去了「这个 Topic 下用户懂了哪些术语」这类联合查询。可以接受：那是统计需求，不是教学需求；真要看，按术语名去 `card` 里搜也够了。

## 不注入，让模型自己查

术语清单一个字都不进上下文。全局 `USER.md` 里只写一段引导，告诉模型有这张表、可以用数据库工具读。查不查、查什么，模型自己判断。

这与 `materials/index.md` 是同一个模式：**程序负责让模型知道有这个东西、怎么取，不替它决定什么时候需要。** 两种注入方案都更差——

- 全量注入：用户学到几百个术语后挤占预算，且绝大部分与这一轮无关。
- 按相关性筛选注入：要求程序猜「这一轮要讲什么」。猜不准，还引入一层无法调试的启发式——用户抱怨「它又讲了我已经会的」，你分不清是筛选漏了还是模型没理解。

模型自己判断更准，因为只有它知道这一轮在讲什么。代价是它可能忘了查，后果是把已懂的东西又讲一遍——「这次表现不够好」而不是「数据错了」，按 ADR-0014 归提示词管。

于是 `glossary` 不需要向文件反向投影，和其他表一样只被工具读写。

## Considered Options

### 术语表也存库，文件是投影

和 `AGENTS.md` / `style.md` 一样让数据库单向做源。否决：术语表是模型在学习过程中高频编辑的散文，每改一个词都要过一次数据库写入 + 文件重写，而它没有任何前端渲染需求。文件进库的判据是「前端要读写」（见 `数据库与目录结构设计.md` 的存储边界），术语表不满足。

### 不分层，只有全局表，取消工作区 GLOSSARY.md

否决：本工作区的用词统一是刚需，而它需要包含大量「正在学、还没彻底懂」的词。全局表不该装这些。

### 加 confidence 分数代替二元门槛

否决：分数会诱导 AI 把半懂的也塞进来，标个 0.6 敷衍过去，于是「用户已掌握」这个信号就废了。门槛必须是二元的、有确认动作的。

## Consequences

- 需要一个提议工具（固定写 `proposed`）、一个查询工具（只返回 `normal`）和 WebUI 的确认入口。提议工具的行为与制卡工具同构：固定 status、不物理删除。
- `term` 全局唯一，重复提议由工具直接拒绝——精确匹配归代码（见 ADR-0017 的同一原则）。
- 查询工具只返回 `normal`：未确认的记录不能影响讲解行为（见 ADR-0005）。
- 全局 `USER.md` 里那段引导是固定文本，不随数据变化，所以不需要程序维护。
- 这张表是 schema 里唯一的孤立表，没有外键进出。这是设计意图，不是遗漏。
