# Teach Style 可在 Pi Session 运行期切换

- 状态：已采纳
- 日期：2026-09-09
- supersedes：`CONTEXT.md` 中「开始时选定提示词模板与教学风格，之后不变」里关于教学风格的部分

## 背景

MVP 把 Agents Md 与 Teach Style 一起当作「开对话时选定、之后不变」的静态设定。真实使用中这两者的稳定性诉求并不相同：

- Agents Md 决定这次对话「做什么」（新学、复习、答疑）。中途改变它等于换了一次对话的目的，历史消息会与新职责脱节。
- Teach Style 只决定「怎么说话」。同一次学习里，用户完全可能先要循序渐进的讲解，理解之后转为苏格拉底式追问。此时强迫用户新开对话，会把已经建立的上下文丢掉——代价与收益完全不成比例。

技术上，Teach Style 通过 `appendSystemPrompt` 进入会话，而系统提示词只在 Agent 构造时读取一次。因此「改数据库 + 改 `style.md`」对已经运行的会话没有任何影响，只改前端显示更是纯粹的假象。

## 决策

Teach Style 允许在 Pi Session 运行期切换，Agents Md 不允许。

切换按以下顺序执行，任何一步失败都不进入下一步：

1. 校验目标 Teach Style 存在（`null` 表示不使用风格，是合法值）。
2. 若该 Pi Session 正在回复，返回 409，不做任何写入。
3. 更新 `pi_session.teach_style_id`。
4. 重新投影该 Pi Session `work_path` 下的 `style.md`（清空风格时写入空文件，不删除文件）。
5. 若会话当前是活的：`shutdown()` 后按稳定 ID 重新 `open`，让新的系统提示词生效。

重开使用与「空闲回收后恢复」完全相同的路径：`SessionManager` 按 `pi_session.id` 打开原 JSONL。因此重开后 `pi_session.id`、JSONL 文件路径、历史条数与已选模型都不变，用户看到的是同一段对话。

助教 Pi Session 拒绝切换（403）：它的行为契约是固定的。

## 后果

- 用户可以在一次对话中改变教学口吻，不必为此丢掉上下文。
- 切换有明确成本：会话要重建一次。因此界面上必须先确认再执行，并说明「历史与模型保留」。
- 运行中禁止切换，避免在一次回复的中途更换系统提示词，产生前后不一致的回答。
- 验证必须断言「新风格文本真的出现在重建后的系统提示里」，而不是只断言数据库与文件——这是区分真实生效与假生效的唯一证据。

## 为什么 Agents Md 不跟进

Agents Md 决定工具职责与产出形态。中途更换会让已发生的工具调用、已产出的文件与新职责冲突，且无法通过重建会话消除这种冲突。真实需求「换一种做法」对应的动作是新建对话，而不是原地改造。

## 否决方案

### 不重开会话，只改数据库与 `style.md`

否决。系统提示词只在构造时读取，这样做在当前轮之后仍然不生效，属于假开关。

### 重开时新建 JSONL

否决。等于丢失历史，与「切换风格而非换对话」的意图相反。

### 允许运行中切换并中止当前回复

否决。用户没有要求中止；静默丢弃一次已经在跑的回答是更糟的副作用。返回 409 让用户自己决定何时切。
