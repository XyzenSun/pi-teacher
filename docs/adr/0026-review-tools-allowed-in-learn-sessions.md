# 学习对话可取卡判定，但提示词标记为反模式

`review_get_due_cards` 与 `review_submit_ratings` 在学习对话**不硬拒**——工具面放行，但提示词把「学习对话中穿插复习」明确写成反模式：默认不发生，用户明确要求时模型照做。

## 为什么不硬拒

这是**行为倾向，不是不变量**（ADR-0014 的分工）。硬拒该留给「验证不了就会出错的事」，而不是「不推荐的事」。代码层拒绝学习对话取卡，挡掉的其实是用户的自主权：用户学到一半想顺手过两张卡，模型回一句「请先打开复习对话」——比在当前对话里干完更糟。

工具面保持干净也有一层实际意义：判定工具的硬约束（防串卡——只接受本会话取过的卡）不需要知道自己在哪种会话里，逻辑少一条分支。

## 为什么标反模式

学习与复习是两条语义不同的路径：学习对话推进新知识，复习对话巩固已有。模型在学习对话里**自发**取卡会打断教学节奏——这是「这次表现不够好」级别的判断错误，归提示词管。

提示词的写法分两句，缺一不可：

1. 「不要在学习对话中主动提议或发起复习」——默认姿态。
2. 「用户明确要求在当前对话复习时，照做，不要推诿」——用户主权压过默认姿态。

`review_log` 不记来源（ADR-0021），学习对话里发生的判定与复习对话的判定写同一张表、对 FSRS 优化同样有效，不需要任何特殊处理。

## Consequences

- `工具定义.md` 的可见性矩阵更新：学习对话对 `review_get_due_cards` / `review_submit_ratings` 从「待定」改为「✓（反模式）」。
- 学习提示词模板（`agents_md` 的 `learn` 类）要写进上述两句；复习模板不需要——复习对话取卡是正模式。
- 判定的 rubric（ADR-0019）在学习对话同样适用，四档标准不因会话类型而变。
