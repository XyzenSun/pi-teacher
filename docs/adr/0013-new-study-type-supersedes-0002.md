# 制卡开关挂在对话上，用布尔而非三档

**学习与复习是两类不同的活动**，不再有「短期空间 / 长期空间」之分。每次对话在开始时决定是否制卡：`pi_session.enable_make_card`，默认开。

原先这是一个三档枚举（默认 / 禁止 / 激进），挂在学习空间上。两点都改了。

## 为什么从三档收窄为布尔

「默认」与「激进」的差异是制卡判据的松紧，这是行为倾向，属于提示词的领地（见 ADR-0014）。把它做成枚举字段，等于用数据库列去表达一个本该由提示词表达的东西——结果是代码里多一个分支，提示词里还得再写一遍这个分支对应什么行为。

判据松紧现在由 `agents_md` 模板决定。「新学」模板和「新学不制卡」模板是两套提示词，用户觉得某个模板制卡太少，改模板正文即可，不需要动 schema。想要「激进」，就写一套激进的模板。

剩下的只有一个真正的硬开关：**要不要制卡**。这是布尔。

## 为什么从工作区挪到对话上

同一个工作区里，这次想深入学并制卡，下次只想快速过一遍不留痕。制卡意图是开一次对话时的选择，不是工作区的固有属性。

原先的理由是「同一件学习任务下的每场对话应受同样的制卡约束，否则用户每开一场都要重新决策」。但决策成本极低——它就是新建对话时的一个勾选框，默认勾上。而挂在工作区上的代价是：想临时关掉制卡就得改工作区配置，改完还得记着改回来。

提示词模板、教学风格也都挂在对话上（见 ADR-0010），制卡开关与它们同级，一起在开对话时选定。

## 复习对话也可制卡，但须克制

复习对话不归属任何学习工作区，但同样持有 `enable_make_card`，默认开。用户既然在复习这块内容，说明它本来就是要长期保持的，此时发现新盲点是好事，不该被阻断。

但判据比学习对话更严：**只有在复习中暴露出新问题、或由当前卡片引伸出新知识时才制卡**。复习的本意是巩固已有卡片，不是借机扩张卡片集。这条写在「复习」提示词模板里，是提示词约束而非硬规则——「克制」本身是判断，无法表达成布尔条件。

典型场景：复习「Java 内存模型」时答错，讲解过程中发现用户对 `happens-before` 毫无概念——这值得单独成卡。而仅仅是把原卡答对了，不构成制卡理由。

## 助教对话不制卡

助教是答疑角色，不推进课程，也不制卡。`enable_make_card` 对助教对话无意义，工具层直接拒绝，不看此字段。

## Consequences

- 判断某次对话能否制卡只看 `pi_session.enable_make_card`，判断点唯一。
- 开关关闭时是硬约束，制卡工具在工具层拒绝，不能只靠提示词约束模型（见 ADR-0014）。
- 制卡的松紧不再有数据库层面的表达。想调整，改 `agents_md` 模板正文。这意味着「制卡倾向」的可观测性依赖于模板命名与描述写得是否清楚。
- 复习对话制卡时，新卡的 Topic 大概率就是当前复习的 Topic，但仍走 ADR-0010 的归类流程，不直接继承。
