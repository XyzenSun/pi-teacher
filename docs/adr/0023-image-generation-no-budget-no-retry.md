# 生图：不控预算、不重试、AI 主动提议

生图能力的三条边界：**预算不由我们控**、**失败不重试**、**触发靠提示词不靠 hook**。

## 预算交给 API 提供商

不做任何预算控制——不记 token 消耗、不设每日上限、不做费用估算。

理由是这件事在提供商侧做得更好：用户在自己的 API key 上设消费上限，那是硬约束、由付费方强制执行、覆盖所有调用方。我们在应用层再做一套，只是一个能被绕过的软限制，还得维护计费规则（各家定价不同、会变），而且永远不如账单准确。

## 不重试

生图失败就报错，告诉用户失败了，不自动重试。

生图是**用户可感知的一次性操作**：提议、同意、等几秒、看结果。失败了用户看得见，想再来一次自己说一句就行。自动重试在这个场景里只会带来两个问题——用户不知道背后重试了几次（费用翻倍），以及失败原因被掩盖（内容策略拒绝重试一百次也还是拒绝）。

这与资料抓取不同：抓取跑在子代理里、用户看不见过程，那里重试是合理的。

## 存到固定目录

图片统一存 `~/pi-teacher/llm-text-to-img/`，不按工作区分目录。

生图 API 通常返回一个有时效的 URL 直链，所以必须下载落盘，不能只存 URL。存到全局目录而非工作区内，因为一张图可能被多个 essence 文档引用，而且生成成本不为零——不该因为删掉一个工作区就丢掉。

下载与落盘由 skill 内部完成，核心代码不碰（MCP 已否决，见 ADR-0027——「skill 还是 MCP」的口子就此关闭）。

## 触发：AI 主动提议，纯提示词

不做 hook、不做周期提醒、不加工具开关。提示词里写一句大意为「当你认为此处生图会帮助用户理解时，向用户提议生成图片」，就这样。

这符合 ADR-0014 的分工：「什么时候该配图」是判断而非不变量，判错了顶多多问一句或少配一张图，属于「这次表现不够好」。而且 ADR-0007 已经定了视觉表达的优先级——默认 Markdown、图表优先 DSL、生图只做记忆锚点——提议时机跟着这个原则走就够了。

提议仍然要用户同意才执行（见 ADR-0005）：生图花钱，不能静默发生。

## Consequences

- 需要在目录布局里加 `~/pi-teacher/llm-text-to-img/`。
- 生图工具的返回值应当是**落盘后的本地路径**，不是原始 URL——URL 会过期，模型拿它写进 essence 文档会留下死链。
- 失败信息要能到用户面前，不能只在日志里。工具返回错误，模型转述给用户。
- 提示词里那句提议引导写在全局 AGENTS.md 还是各学习模板里，待写模板正文时定。倾向全局——它与教学模式无关。
