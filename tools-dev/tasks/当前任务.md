## 已解决的环境/实现问题（2026-09-08 backend-host-mvp 实录）

1. **wrapper 注册表 key 错位：注册用 SDK uuid，查询用 jsonl 路径**
   - 现象：SSE 404、`get_session_stats` 报「会话不在运行」、jsonl 从未落盘
   - 根因：`SessionManager.newSession()` 不传 id 时 `sessionId = uuidv7()`，`registerWrapper` 按它注册；路由层却按 `sessionFile`（jsonl 路径）查注册表，永 miss
   - 解法：`registerWrapper` 双 key 注册（SDK id + jsonl 路径），destroy 时都清；`listRunningSessionIds` 按对象去重
2. **AgentSessionWrapper.onDestroy 单槽会被覆盖**
   - 现象：测试为打点调 `onDestroy` 后，注册表清理回调被盖掉，wrapper 销毁后 key 永留
   - 根因：`onDestroyCallback` 是单槽赋值的私有字段
   - 解法：改成 `onDestroyCallbacks` 数组（registerWrapper 的清理 + 外部监听共存），`finishDispose` 逐个执行并 try/catch
3. **`/api/auth/me` 在 auth router 里但 auth router 挂在 requireAuth 之前**
   - 现象：登录后 `me` 返回 `{username: null}`
   - 根因：`app.use("/api/auth", createAuthRouter(db))` 先于 `app.use("/api", requireAuth)`，me 的 `req.session` 从未被挂
   - 解法：`router.get("/me", requireAuth, handler)` 局部守卫，status/setup/login 仍免登
4. **fork 子进程 `process.send` IPC 在快速 exit 时丢帧**
   - 现象：子进程发 `WRAPPERS_CLEAN=1` 后立刻退出，父进程在 childOutput 里看不到该标志
   - 根因：IPC 消息异步 flush 与 `process.exit()` 竞态
   - 解法：验证标志写 stdout（`console.log`），父进程从输出断言，不依赖 IPC 送达（lifecycle.ts）
5. **card_schedule 表没有 `id` 列（主键是 `card_id`）**
   - 现象：`SELECT id FROM card_schedule ...` 报 `no such column: id`
   - 解法：查询改 `SELECT card_id`（http-smoke 脚本自身 bug，非服务端）
6. **promisify(scrypt) 的 options 重载在 Node 类型下推断不佳**
   - 现象：`promisify(scrypt)` 的 options 参数类型不兼容、derived 是 unknown
   - 解法：password.ts 手工 Promise 包装，`scrypt(password, salt, KEY_LENGTH, options, cb)`
7. **like 通配符 `_` 会把任意单字符当通配**
   - 现象：前缀 `a_` 把 `axb` 也匹配进 `listConversations`
   - 根因：SQL LIKE 里 `_` 匹配任意一字符，未转义
   - 解法：`escapeLike()` 用 `\` 转义 `[\\%_]`（session-reader.ts）
8. **会话 adapter 层要显式 `.ts` 扩展名（NodeNext TS2835）**
   - 现象：bridge 相对导入无扩展名报 TS2307/TS2834/TS2835
   - 根因：NodeNext 模块解析强制显式 `.ts`
   - 解法：全部补 `./xxx.ts`；`@earendil-works/pi-agent-core` 是嵌套依赖，提升进 dependencies 才能 import

## 已解决的环境/实现问题（2026-09-07 开发实录）

1. **due 日期格式必须用 SQLite 文本格式而非 ISO 8601**
   - 现象：card_schedule.due 存 `toISOString()`（`2026-09-07T07:44:01.983Z`），查询条件 `due <= datetime('now')` 永假，取不到卡
   - 根因：TEXT 比较时 `'T'`(0x54) > `' '`(0x20)，ISO 格式恒大于 SQLite 的 `YYYY-MM-DD HH:MM:SS` 格式
   - 解法：`dateToSqliteText()` 统一转 SQLite 格式（fsrs/service.ts）；V8 的 `new Date()` 能解析该格式，读侧无碍

2. **归一化去重的空白处理**
   - 现象：`JVM 的垃圾回收` 与 `JVM的垃圾回收` 判为不同卡
   - 根因：初版「压缩连续空白为单空格」，中文语境里有无空格是同一句话
   - 解法：归一化直接删除全部空白（cards.ts normalizeFront）

3. **typebox 1.3.7（新版拆分包）导入**：`import { Type } from "typebox"` 根入口有 Type 命名空间；`typebox/type/index.mjs` 等子路径没有。踩坑：直接 require 主入口报错，需走 ESM 根入口
4. **`@earendil-works/pi-tui` 不是 pi-coding-agent 的传递依赖可隐式用的**——必须显式 npm install 同版本（0.84.2），否则 ask-user.ts 的 Editor/Key/Text 导入报 TS2307
5. **冒烟直调 ToolDefinition 的类型桥**：execute 签名严格（5 参数），测试代码用 `unknown` cast 桥接（smoke.ts callTool），不污染业务代码类型
6. **run-real 模型解析**：`ModelRuntime.create()` 默认读 `~/.pi/agent/models.json`，用户的 new-provider（openai-completions 兼容端点 + apiKey 字段）可直接被 `getModel('new-provider','deepseek-normal-latest')` 解析，无需额外 auth 配置
7. **models.json 中 apiKey 直接内嵌**（用户环境如此），无需 auth.json——auth.json 是空的 `{}` 也能跑
