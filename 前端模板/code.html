在编写高性能双重检查锁定（Double-Checked Locking, DCL）单例模式时，如果变量不加 volatile 关键字，究竟会在底层引发什么灾难？能否从 CPU 指令重排序、JMM 内存屏障以及 happens-before 传递性的角度做严密论证？

// 存在隐患的 DCL 单例代码示例
public class Singleton {
  private static Singleton instance;
  public static Singleton getInstance() {
    if (instance == null) {
      synchronized (Singleton.class) {
        if (instance == null) instance = new Singleton(); // 关键分配行
      }
    }
    return instance;
  }
}

1. 字节码指令分解：new Singleton() 实际上对应字节码中的三步指令：分配内存空间（NEW）、执行构造函数初始化（INVOKESPECIAL）、将引用地址赋给 instance 变量（ASTORE）。

2. 指令重排的可能性：JVM 和 CPU 在没有强制屏障的前提下，遵循 as-if-serial 原则。若第 2 步与第 3 步之间不存在数据依赖关系，编译器与硬件层可能重排为 1 -> 3 -> 2。

3. 并发竞态场景：若线程 A 执行了 1 和 3，此时 instance != null，但堆内存尚未完成构造函数初始化（半初始化对象）；若此时线程 B 进入第一重判空，将直接拿到半成品对象导致空指针或状态错乱。

4. 解法归纳：利用 volatile 插入 StoreStore 与 StoreLoad 内存屏障，防止写操作与先前的写操作发生重排。

1. 对象创建的字节码三部曲与指令重排机理

在 Java 虚拟机层面，执行 instance = new Singleton() 绝非不可分割的原子操作。底层 JIT 编译器在优化机器码时，将其展开为下列关键操作：

// 1. 分配一块内存空间 memory = allocate();
// 2. 在该内存区域上初始化对象 ctorInstance(memory);
// 3. 将对象引用地址指向该内存 instance = memory;

若缺少有序性约束，JVM 可能会将上述顺序重排为 1 → 3 → 2。在多线程环境中，一旦线程 A 完成了步骤 3，此时变量指针已不再是 null，但其所指的对象其实仍处于未初始化的半成品状态。

Happens-Before 规则的生效点： JMM 规定：对一个 volatile 变量的写操作，先行发生于后面对这个变量的读操作。写 volatile 时，JMM 会在写指令前插入 StoreStoreBarrier，在写指令后插入 StoreLoadBarrier，杜绝了初始化代码被挪到赋值之后的可能。

Q: JMM 中针对 volatile 写操作插入的底层内存屏障分别是什么？其核心目的为何？

A: 包含 StoreStoreBarrier（保障之前的写刷新到内存）与 StoreLoadBarrier（禁止后续读操作与该写重排）。

卡片 #01 · 必背 JMM 模型

什么是 happens-before 先行发生原则？

JMM 提供的有序性承诺：若操作 A 先行发生于操作 B，则 A 产生的影响（变量修改）能被操作 B 观察到。包括程序次序、锁定规则等 8 大规则。

难度：★★★★☆
卡片 #02 · 当前聚焦 Volatile 屏障

Volatile 写操作所插入的硬件内存屏障有哪些？

包含 StoreStoreBarrier（禁止前面写与当前写重排）与 StoreLoadBarrier（禁止当前写与后面读重排），保证对象初始化的安全发布。

难度：★★★★★
卡片 #03 · 模式设计 单例陷阱

DCL 单例未加 volatile 为什么会出现空指针？

因 new 指令重排导致引用提前指向尚未调用构造函数的半初始化内存，其他线程执行外部判空时会直接使用半成品实例。

难度：★★★☆☆
卡片 #04 · 汇编指令 x86 架构

x86 CPU 架构下 volatile 对应哪条汇编前缀？

对应 lock addl $0x0, (%rsp) 指令，锁定总线或缓存行，强制冲刷写缓冲器（Store Buffer）。

难度：★★★★★
卡片 #05 · 原子性 并发限制

为什么 volatile 无法保证 count++ 线程安全？

自增操作包含：读取值、加 1、写回 3 个步骤，volatile 只能保证读写单个瞬间的可见性，无法将 3 步绑定为复合原子事务。
